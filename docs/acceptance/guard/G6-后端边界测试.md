## 一、先说什么叫「能测」

一条边界测试成立的前提是**正确行为已经实现**。如果实现是错的或不存在，只有两种写法：

| 写法 | 后果 | 判断 |
|---|---|---|
| 断言「当前错误行为」 | 把 bug 固化成契约，以后修了还要改测试 | **不可接受** |
| 写一个永远红的测试 | CI 长期红，训练人忽略红灯 | **不可接受** |
| `@Disabled` 的规格（记录正确行为，等实现后启用） | 不拖累 CI，且留下可执行的规格 | **本批采用** |

所以下面的「3 真 + 3 规格」不是缩水，是**把「缺测试」和「缺功能」分开**——这两件事的处置完全不同。

> **2026-11-13 复核**：这个分法本身就是对的，它让「缺功能」那三条带着证据进了 `DEFERRED.md`，而不是被当成「测试没写」糊过去。**但它们后来确实被实现了**——所以本节的分法有效，结论会过期，**过期的是结论，不是方法**。

## 三、为什么第 4 条（立案幂等）不写

三个理由，按重要性排：

1. **根因不在服务端。** 服务端的幂等键逻辑是对的（`CaseServiceImpl.create:121` 用
   `IDEM_PREFIX + userId + ":" + idempotencyKey` 做 Redis 键）。真正的重复立案风险来自客户端
   **每次调用都生成新 key**——那个已在 G5 删除（`features/case/api/client.ts` 不再有
   `newIdempotencyKey`），并由 ESLint `no-idem-key-in-api` 与「api 层禁 `Math.random`/`Date.now`」两道拦住。
   给已经正确的服务端再补一个重型集成测试，不如把根因拦住。
2. **同类机制已有覆盖。** `RechargeIdempotentTest` 覆盖同一套 Redis 幂等模式（充值下单）；
   案件幂等与它是同一份实现的两次调用，不是两套机制。
3. **测试成本与脆弱度不成比例。** `CaseCreateBO` 是四步表单全量结构，且 `create` 有前置校验。
   造一份合法 BO 需要几十行夹具，且上游字段一变测试就跟着坏——**这种测试的维护成本会超过它拦住的东西**。

> **这条是判断，不是事实。** 如果以后真出现「同 key 建出两案」的线上问题，
> 就应该补一个真实链路测试（含并发），而不是当初先写一个猜出来的。

## 四、本次修为代码的两处

### 4.1 `SocialQueryService.unfavorite` 删除「先查任意用户再判 403」（DRIFT-014）

```java
// 删除前：查任意用户对该目标的收藏行（不带 user_id、不带 ORDER BY），再比较 userId
List<SocialAction> others = ... .eq(targetId).isNull(deletedAt).last("LIMIT 1");
if (!others.isEmpty() && !userId.equals(others.get(0).getUserId())) {
    throw new BusinessException(ErrorCode.COMMON_FORBIDDEN);
}
```

删掉的理由不是「看着多余」，是它**两个致命问题**：

1. **行为取决于数据库返回哪一行。** 实测：同一 token 下 `targetId=3`（被别人收藏）返回
   `401008 无权限`，`targetId=99`（无人收藏）返回 `200` —— **与预期完全相反**。
2. **它校验的对象本来就不可能是别人的行。** 下面调的
   `socialActionService.unfavorite` 的 UPDATE 条件里已经带 `user_id = userId`，
   物理上删不到别人的收藏。所以这段预检**既拦不住越权，只会误伤合法用户**。

正确语义：取消一个「自己没收藏」的目标 = 幂等成功（0 行受影响），不是 403。

### 4.2 `CorsConfig` 补两个暴露响应头

`X-Pay-Pwd-Remaining`（支付密码剩余次数）服务端一直在发，但没进暴露列表 →
**浏览器端 `fetch` 读不到任何自定义响应头** → 设计稿要求的「还可试 N 次」永远显示不出来。
`Retry-After` 同理（限流/锁定等待秒数）。两个都已加，`CorsExposedHeadersTest` 守住。

## 五、怎么跑

```powershell

# 「Could not resolve placeholder 'FAZE_DB_URL'」整类报错（不是跳过）
node logs\run-backend-test.mjs SocialFavoriteMultiUserTest CorsExposedHeadersTest
```

`logs/run-backend-test.mjs` 是本地启动器（**不进仓库**，`logs/` 已 gitignore）：
它用 Node 解析 `deploy/.env` 再传给 mvn。为什么不用 PowerShell 读 `.env`——
`deploy/.env` 是 LF + UTF-8，Windows PowerShell 5.1 的 `Get-Content` 会把
「中文注释行 + 下一行键值」并成一行，导致紧跟注释的 `FAZE_DB_URL` 注入不进去（已实测踩到）。
