# G8 承诺性注释校验

- 日期：2026-11-11
- 依据：《说辞统一与工程护栏计划》G8「`check:contracts`（承诺性注释校验）」
- 结论：**计划原本要的「每条承诺必带 `@契约` 标记」被推翻**，改为「清单化 + 漂移比对」。实测 444 条承诺性注释、1 条范围承诺违规（台账内）。

---

## 一、计划原本要什么，为什么没这么做

计划 §2.6 写的是：凡注释出现 `幂等` / `重复提交返回` / `影响全 App` / `自动` / `必须` / `保证` 等关键词，**必须带 `@契约` 标记或 `@未实现` 标记**。

先按这个方案统计了一遍存量：

| 关键词 | 命中数 |
|---|---|
| 幂等 | 320 |
| 保证 | 99 |
| 重复提交 | 22 |
| 重复点 | 3 |
| **合计** | **444** |

**绝大多数是「说对了的」**，例如：

- `content/api/favorite.ts:11`「服务端两个方向都幂等：重复收藏 / 重复取消都返回成功」——这是真的；
- `trade/api/recharge.ts:43`「幂等键（同一次点击的重试必须复用同一个值）」——这是真的，而且 G5 刚把它变成强制。

给 444 条正确注释全部加 `@契约` 标记，结果是**人开始批量刷标记**——标记失去信息量，检查等于没有。这是「形式主义护栏」，比没有护栏更消耗信任。

**所以改成两件事**：

1. **清单化**：把 444 条承诺扫出来写进 `docs/facts/contracts.json`（进仓库、可 diff）。不要求人改注释，但要求**承诺的总量是可见的**——新增一条承诺时清单会变，CI 会红，人必须看一眼「这句是真的还是吹的」。
2. **机器能判假的直接判**：i18n 用户可见文案里写「影响全 App」而实现只影响设置页——这类不需要人判断。

---

## 二、机器能直接判假的那一类（1 条，台账内）

**`profile.fontSizeNote` 写着「字体会影响全 App 的正文与按钮文字」**，而实现只影响设置页（DRIFT-002）。四语言同句。

这条**没有修**，登记在 `scripts/facts/contracts-known.json`，理由写在台账里：

> 这是用户可见文案，修它要四语言同步改。而「全 App 生效」是不是本来该做还没最终拍板：
> 改文案 = 承认只有设置页生效；改实现 = 让字号全局生效（工作量大，且要和四语言字体的度量一起验）。
> **在拍板前改文案，等于替产品做了一个决定。**

关闭条件：DRIFT-002 拍板后（改文案或改实现二者之一），四语言同步改完，删掉台账条目。

---

## 三、`contracts.json` 怎么读

```
totals.promises        444   承诺性注释总数
totals.scopeViolations 1     范围承诺违规（机器判定）
byKeyword              幂等:320 / 保证:99 / 重复提交:22 / 重复点:3
promises[]             每条：文件 / 行号 / 命中关键词 / 注释原文（截 200 字）
scopeViolations[]      每条：文件 / 行号 / 原文
```

**注意 `promises` 不代表说错了**——它只说明「这句注释提到了承诺」。判定真假是人的事，清单的作用是让「新增承诺」不可悄悄溜过。

---

## 四、CI

```yaml
- name: 承诺性注释与文案（清单不漂移 + 范围承诺在台账内）
  run: node scripts/facts/check-contracts.mjs --check
```

两道判定：

| 判定 | 失败含义 |
|---|---|
| `contracts.json` 与源码不一致 | 有人新增/删除/改了承诺，但没重跑清单——**新承诺没人看过** |
| 范围承诺违规数 > 台账 | 又多了一条「文案承诺的范围大于实现」 |

---

## 五、这条护栏的已知盲区

1. **只能发现「新增了承诺」，发现不了「承诺与实现不符」**（除了「影响全 App」那一类）。判断一句「服务端幂等」是不是真的，需要读实现——那是 code review 的事。
2. **关键词表是手写的**。新词（如「一定会」「绝对不会」）不会被抓，要人工加。
3. **只扫注释与 i18n 文案**，不扫产品文档里的承诺（那由 DRIFT 表承担）。
4. **后端 Java 注释占了大多数**（幂等 320 条里大半在后端），前端只占小部分——这与「幂等是服务端机制」的事实一致。

---

## 六、这一批没有做的事

1. **没有给 444 条承诺逐条验证真伪**——那需要逐段读实现，是 code review 的工作量，不是脚本的。
2. **`profile.fontSizeNote` 没改**（台账内，等 DRIFT-002 拍板）。
3. **没有把「承诺」与 DRIFT 行做自动关联**（计划里的 `@契约 <DRIFT-ID>`）。当前 444 条里只有少数有明确 DRIFT 关联，强制关联会大量误报；等清单稳定后再考虑。
