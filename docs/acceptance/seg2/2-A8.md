# 段 2 锚点 `2-A8` 超时与幂等 — 证据

> **判定：通过（幂等为端到端实测；两条超时为单测级 + 调度实跑日志）。**
> 原文：「① 下单后不支付等超时；② 连点提交订单 3 次」→「① 订单自动关闭、余额退回且有流水；
> ② 只产生 1 个订单」。

## ② 幂等（端到端实测）

| 项 | 实测 | 出处 |
|---|---|---|
| 同一 `Idempotency-Key` 连发 3 次 | 三次都返回同一 `orderId=1`；`orders` 只有 1 行 | `G2-order-pay.md` 第 32 行 |
| 重复支付 | 已支付订单再调 `pay` → `duplicated=true`，**不重复扣款** | `OrderServiceImplTest` |
| 服务端兜底 | Redis 幂等占位（`tryStart` / `bind` / `release`），失败释放 | 同上 |

## ① 超时（两条）

| 项 | 实测 | 出处 |
|---|---|---|
| `PENDING` 15 分钟超时关闭（**不涉及退款**） | `OrderTimeoutServiceTest` 6 项：关单 / 已支付跳过 / 不存在 / 接单超时退款 / 已接单不退款 / 未知类型抛 | G2 §六 |
| `PAID` 30 分钟无人接 → 自动全额退款 | 同上（接单超时退款用例）+ `OrderRefundService.autoRefundFull` | G2 / G4 |
| 调度器实跑 | `OrderCloseTask` 每 30 秒扫描，日志可见「扫描触发 / 本轮没有到期任务」 | `G3-lawyer.md`（修 `@Scheduled` 时实测） |

## 「余额退回」的解释

按负责人 2026-11-01 确认：`PENDING` 阶段本就没扣钱，所以「余额退回」指
**`PAID` 后 30 分钟无人接单的自动退款**；两条都要验（已验，见上表）。

## 已知局限

- 两条超时都是**单测级**（把时间参数注入，不在端到端脚本里干等 15/30 分钟）；
  调度器实跑日志证明扫描器在工作，但「真实等到超时」未跑（成本 15~30 分钟）。
