# 段 2 锚点 `2-A6` 退款闭环 — 证据

> **判定：通过（全额 / 部分 / 驳回三路径 + 对账差异 0）。**
> 原文：「A 发起退款申请 → PC A-12 审批通过」→「余额恢复、流水新增 1 条退款记录；
> A 端订单状态与退款状态正确；全额 / 部分退两种都验」。

## 逐条对照（三路径，全部真实 API + SQL）

| 路径 | 关键实测 | 出处 |
|---|---|---|
| 全额（订单 11 / 退款单 8） | 订单 `refunding → refunded`；余额 `19318 → 25318`（+6000）；`balance_flow` 609 `refund +6000`；`payment_record` 13 `-6000`；退款单 `refunded` + `transaction_id=BAL-609` | `G4-refund.md` §3.2 |
| 部分退（订单 12 / 退款单 9） | 订单回到**退款前状态**（不是 REFUNDED）；退款单 `refunded`；流水 `biz_id=refundId` | 同上 §3.3 |
| 驳回（订单 11 / 退款单 7） | 退款单 `rejected` + `audit_remark`；订单 `refunding → refund_rejected → paid` | 同上 §3.1 |
| 幂等键 | 退款入账幂等键改为 `refundId`（曾因 `orderId` 与旧数据碰撞导致「审批成功但余额没变」，已修 + V201 迁移） | 同上 §五 |
| 对账 | 余额恒等式差异 **0** | 同上 §七 |

## PC 审批入口

A-12 订单详情页的退款单表里只有 `applying` 行有「审批」按钮，弹窗驳回必填原因，
调 `POST /admin/refunds/{id}/audit`；审批动作写 `operation_log`
（`ORDER_REFUND_APPROVED` / `ORDER_REFUND_REJECTED`，G4 + G9 已验）。
页面级截图缺（同 `2-A3` 局限），接口与审计证据齐全。
