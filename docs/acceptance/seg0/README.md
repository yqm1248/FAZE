# 第 0 段验收证据索引（`docs/acceptance/seg0/`）

> **这是什么**：第 0 段（可安装底座 + 三项探针）8 条验收锚点的证据总入口。
> **依据**：《第 0 段工作流》§四 4.9（目录规范 / 命名规则 / `_meta.md` 必填字段）。
> **注意**：本目录是**验收证据**，不是文档基线资产（类比 `docs/CHANGELOG.md`，不进 `BASELINE.md` 的 38 份清单）。

## 一、目录结构

```text
docs/acceptance/seg0/
├─ README.md                     # 本文件
├─ 0-A1/ ~ 0-A8/                 # 每条锚点一个目录，目录名只能是锚点编号
│   ├─ _meta.md                  # 必填；缺它该锚点按「未验」处理
│   └─ <锚点编号>_<证据含义>-<yyyyMMdd-HHmmss>.<ext>
└─ _artifacts/                   # 大数据不进 git 时放这里（须在 _meta.md 记 sha256 + 来源 URL）
```

## 二、命名与格式（硬规则）

- 命名：`<锚点编号>_<证据含义>-<yyyyMMdd-HHmmss>.<ext>`，例 `0-A3_progress-20261102-193500.png`；
- 时间戳：`Get-Date -Format 'yyyyMMdd-HHmmss'`（Asia/Shanghai）；
- 后缀：截图 `.png`（原始分辨率）、命令输出 `.txt`（UTF-8）、结构化返回 `.json`、UI 树 `.xml`；**不用 `.log`**（`.gitignore` 有 `*.log`，进不了 git）；
- 禁止的命名：`1.png`、`截图.png`、`0-A1.png`（无时间戳）、`0-A1_最终版2.png`。

## 三、`_meta.md` 必填字段（缺任一项 = 该锚点未验）

执行人 / 执行时间（ISO-8601 带偏移）/ 机型 / 系统版本 / ROM 构建号 / 设备序列号 / 是否物理机 / 包名与版本 / 应用构建号 / 代码版本（`git rev-parse --short HEAD`）/ 结论（通过 / 不通过 / 阻塞挂账）/ 偏差说明（不通过或阻塞时必填）。
