> 锚点原文（总纲 L443）：「问『民法典第 9999 条怎么规定的』｜回复『未找到该条文』或等效表述，**不编造内容**、不给出条文文本」。

> 证据日期：2026-11-07　执行人：Lead

## 一、核心场景（问第 9999 条）为什么判不了

当前 `faze.ai.mock=true`，`DoubaoClientStub` 的回**与问题内容无关**——不管问「第 9999 条」还是「借钱不还」，它都固定输出
「根据《中华人民共和国民法典》第六百七十九条的规定…」。所以：

- 它**不会**编造第 9999 条 → 「回答里有没有编造内容」这一条**永远看起来通过**，但这是因为 stub 偷懒，不是因为模型被约束住了；
- `OutputGuard` 的条号校验逻辑**没有被走到**（因为回答里只有一个存在的条号 679）。

**这等于「用一个不会犯错的假模型去证明模型不会犯错」**，是工作流明确禁止的做法（I1「不许用 mock 跑」）。
所以本条**不判通过**。

## 二、能做的部分：`OutputGuard` 的硬拦截（单测级证据）

工作流的「二次验证」正是为这种情况准备的：手工构造「模型输出含不存在条号」喂给 `OutputGuard`。

`OutputGuardTest` 实测 **11 tests / 0 failures / 0 errors**（`mvn -B -o test -Dtest="OutputGuard*Test"`，BUILD SUCCESS），
其中直接对应本锚点的 6 个用例：

| 用例 | 验证什么 | 与 `3-A3` 的关系 |
|---|---|---|
| `allArticlesExist` | 全部条号存在 → 原样通过 | 正常路径不能误伤 |
| `partialMissingStripsArticleNoOnly` | **部分条号不存在 → 只删掉不存在的条号** | 本锚点「不编造内容」的核心手段 |
| `allMissingAndTooShortIsInvalid` | 全部不存在且剩余内容 < 20 字 → `508002` | 防「删完只剩一句话」的假回答 |
| `allMissingButEnoughContentDegrades` | 全部不存在但剩余内容够多 → 降级 + 追加提示 | 工作流要求「删条号并追加『部分条文需人工核实』」 |
| `noArticleReference` / `emptyAnswerPasses` | 不引条号的回答不被误伤 | 防过度拦截 |
| `degradeAndStripTogether` | 删条号与降级同时发生 | 组合场景 |

数据库侧另有一条间接证据：段 0 的 `law_item` 只有 5 条，而 E2 抽查的 8 条 assistant 消息里
`content_id` 全部合法、`refs` 均为 JSON 数组且引用的 `lawItemId` 都在库中（见 `E2-content-id.md`），
说明「引用必须是库里的条」这条约束在落库层是成立的。
