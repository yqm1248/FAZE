## 一、配额显示（实测）

`/agent` 页输入框上方一行小字「今日还剩 N 次」，数据来自 `GET /api/v1/app/ai/quota`。

实测递减序列（同一账号 user 1）：

| 动作 | 页面显示 | 服务端 `used` |
|---|---|---|
| 进入页面 | 今日还剩 35 次 | 15 |
| 发问 1 次 | 34 | 16 |
| 发问 3 次（3-A5 连发） | 30 | 19 |

→ 每次提问扣 1，`limit=50`，`resetAt=次日 00:00+08:00`。截图 `img/F5-quota-390.png`。

`useAiQuota` 的注释写明「配额是服务端权威值，每轮 `done` 后重新拉一次，不用本地 -1 猜测」——
**这条在断网场景下有一个已知缺口**：3-A8 实测时页面数字滞后一格（服务端 16→17，页面仍显示 34），详见 `3-A8.md` 第五节第 2 条。

## 三、断线重连（已实测，锚点 `3-A8`）

完整证据见 `3-A8.md`。结论摘要：

- CDP 断网 4 秒 → 恢复 → **回答完整接上**（130 字 + refs + AI 标识）；
- **不新建气泡**（1 user + 1 AI，共 2 个）；
- 服务端 `used` **只 +1**（16→17）；
- 该会话 **1 条 user + 1 条 assistant**，assistant 有 `content_id`。

实现细节（读代码核对）：最多 3 次重连、退避 1s→2s→4s、带 `fromSeq`（用「已收到 delta 条数」推算）、
复用同一 `assistantId` 与 `streamPath`、用户主动停止后不重连。

## 四、配额为 0 时禁用输入框（未实测）

判据：「`used` 达到 `limit` 时输入框禁用 + 提示『今日次数已用完，明天再来』」。
未测原因：把 `ai_daily_quota` 改成 0 或把 used 灌满会污染配额数据（Redis 计数），
且会把账号锁到次日。代码里 `exhausted = remaining === 0` 的分支存在（`useAiQuota` L67 返回），
但**没有运行时证据**。
