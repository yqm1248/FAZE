> 锚点原文（工作流 §四 `3-A8` / I2 第 3 条）：「生成中途开飞行模式 10 秒 → 关掉 → 自动重连 → 回答接上；查 `GET /app/ai/quota` 的 `used`：**只 +1**；查 `ai_message`：该会话只有 **1 条** assistant 消息」。
> 证据日期：2026-11-07　执行人：Lead

## 一、为什么用 CDP 断网而不是「飞行模式」

本机无真机、无模拟器（`adb devices` 为空、无 `ANDROID_HOME`），飞行模式做不了。
替代方案：RN Web 跑在真实 Chrome 里，用 CDP 的 `Network.emulateNetworkConditions { offline: true }`
断掉整个页面的网络——对前端 fetch 的效果与飞行模式等价（连接被拒），能真实触发 F5 的重连逻辑。

**不是**「用 mock 假装断网」：断网是浏览器级真实的网络切断，重连是 `useAiStream` 的真代码路径
（最多 3 次、1s→2s→4s 退避、带 `fromSeq`、复用同一 `assistantId`）。

## 三、三条判据的实测

### 3.1 回答是否接上

- `assistantBubbles = 2`：1 个用户气泡 + 1 个 AI 气泡——**没有出现第二个 AI 气泡**（工作流要求「重连不新建气泡」）。
- `hasGeneratedLabel = true`、`hasLawRef = true`：AI 标识与 `refs` 引用块都在。
- `bodyTail` 里是**完整的 130 字回答**（含「以上内容由 AI 生成，仅供参考」结尾），不是半截。

### 3.2 `used` 是否只 +1

时间线（同一账号 user 1，均通过 `GET /app/ai/quota` 读）：

| 时点 | used |
|---|---|
| 发含手机号问题（会话 13）后 | 15 |
| F3 流式测试发问（会话 14）后 | 16 |
| **断网重连测试（会话 15）后** | **17** |

→ **+1**，符合「断线不重复计费」。

### 3.3 `ai_message` 该会话是否只有 1 条 assistant

```sql
SELECT c.id AS conv, COUNT(m.id) AS msgs, SUM(m.role='user') AS user_msgs, SUM(m.role='assistant') AS asst_msgs
FROM ai_conversation c LEFT JOIN ai_message m ON m.conversation_id=c.id
WHERE c.user_id=1 GROUP BY c.id ORDER BY c.id DESC LIMIT 3;
```

实测：

```text
conv  title                              msgs  user_msgs  asst_msgs
15    断网重连测试：借钱不还怎么办          2        1          1
14    借钱不还怎么办，只有转账记录           2        1          1
13    我手机号13812345678，老板拖欠工资…     2        1          1
```

会话 15 恰好 1 user + 1 assistant；assistant 行 `id=67, len=130, content_id 非空`（内容编号已生成）——**没有因为重连产生重复落库**。

## 四、判定

| 判据 | 结果 |
|---|---|
| 断网 → 恢复 → 回答接上 | ✅ 完整 130 字回答 + refs + AI 标识 |
| 重连不新建气泡 | ✅ 只有 2 个气泡（1 user + 1 AI） |
| `used` 只 +1 | ✅ 16 → 17 |
| 该会话只有 1 条 assistant 消息 | ✅ 1 user + 1 assistant，有 `content_id` |

**结论：通过。**

## 五、没做到的 / 发现的缺陷（如实记录）

1. **不是真机飞行模式**：用 CDP 断网等价模拟。真机上还有「系统级网络切换、WebSocket/HMR 干扰、后台挂起」等差异，**建议段 4 开始前用真机复测一次**。本条不因此判「未通过」，但证据强度低于真机。
2. **页面上的配额文本没刷新（F5 的小缺陷）**：`quotaBefore` 与 `quotaText` 都是「今日还剩 34 次」，但服务端 `used` 已经 16→17（真实剩余 33）。也就是说**配额扣对了、页面显示滞后了一格**。
   原因推测（未深挖）：`useAiQuota` 在 `done` 后 `refresh()`，而断网重连的 `done` 事件可能没走到刷新分支（或刷新请求在恢复瞬间失败后没有重试）。
   影响：`3-A8` 的判据本身不受影响（判据是服务端 `used` 与消息条数），但 F5「用一次变 49」的验收在断网场景下会看到旧值。**已记为 F5 待修项，不算本锚点失败。**
3. **没有录屏**：工作流要求「录屏」，本机用 CDP 脚本 + DOM/DB 断言代替。脚本本身是可复现的（附在文末路径），但录屏这一形式未提供。
