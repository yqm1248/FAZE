## 二、前端消费的接口契约（3 个，去掉 review）

| # | 方法与路径（前端写相对路径，由 `/biz-api` 前缀拼） | 说明 |
|---|---|---|
| 1 | `GET /api/v1/admin/ai-conversations?userId=&beginTime=&endTime=&pageNum=&pageSize=` | 列表，RuoYi `TableDataInfo`。行字段：`id, userId, userName, title, lang, createdAt, updatedAt, deletedAt, questionSummary, refCount`；**含已软删会话** |
| 2 | `GET /api/v1/admin/ai-conversations/{id}/messages` | `R<data>`，data = `{conversation, messages, currentLawItems}`。`messages[].refs` 已是解析后的数组（D4 schema：`lawItemId/lawCode/lawName/articleNo/content/effectiveDate/status`）；`currentLawItems[]` = 当前 law_item 的 `lawItemId/status/isEnabled/effectiveDate/expireDate/updatedAt`（做「快照 vs 当前」用，避免前端 N+1） |
| 3 | `GET /api/v1/admin/ai-conversations/{id}/export` | 文件流（`Content-Disposition: attachment; filename="AI-CONV-<id>-<yyyyMMddHHmm>.json"`，Asia/Shanghai）；服务端写 `operation_log(action=AI_CONVERSATION_EXPORT)`、回写 `is_exported/export_urls`；单会话 >200 条截断（文件内 `truncated`） |
| — | ~~`POST /admin/ai-conversations/{id}/review`~~ | **不做**（§零.3 第 9 项：不要复核） |

业务 axios 实例的响应拦截器对非 R 结构原样返回，所以导出拿到的是 `Blob`；**响应头（Content-Disposition / X-Export-Truncated）拿不到**（拦截器只回 body），因此下载文件名在前端按同一格式拼、截断标记从文件 JSON 的 `truncated` 字段读（见 §五）。

- 消息区：
  - `role='user'`：右侧气泡 + `HH:mm`；
  - `role='assistant'`：左侧气泡，头部 `AI 生成` 标签 + `HH:mm` + 「用时 X.X s」+ 模型；正文 `pre-wrap` 保留换行；底部显示 `内容编号`（若后端返回）。

## 四、「快照 vs 当前」实现说明

- 数据源：`GET /{id}/messages` 返回的 `currentLawItems[]`（后端按 `lawItemId` 给当前状态），**不逐条回查** `/admin/law-items/{id}`（避免 N+1）。
- 页面按 `String(lawItemId)` 建 Map（Long 已由 Jackson 序列化为字符串，统一用字符串键）。
- 判定规则（`snapshotNotice(ref)`）：
  1. 当前行不存在 → 「该条文的当前版本已查不到，以下为引用当时快照。」（法条被清理的兜底）；
  2. `current.status !== ref.status`：
     - `current.status === 'repealed'` → 「该条文已于 <日期> 失效，以下为引用当时快照。」；
     - 其他（如 `active → amended`）→ 「该条文已于 <日期> 更新，以下为引用当时快照。」；
  3. 状态相同但 `isEnabled=0/false` → 「该条文已于 <日期> 失效，以下为引用当时快照。」；
  4. 无变化 → 不显示提示行。
- 日期优先级：`current.expireDate`（修正时 = 修正生效日）→ 否则 `current.updatedAt`（只取日期）。
- 证据：
  - mock 布局自查截图 `h2-a28-refs-mockdata.png`：三条 refs 分别命中「已更新」「已查不到」分支（固定数据，仅布局/交互证据）。
  - 真实数据：`h2-a28-refs.png`（选中一条有引用的真实会话，refs 快照渲染正常；当前开发库法条还没被修正过，所以「快照 vs 当前」提示为 0 条——属正常，不算失败）。
  - 真实数据触发「已更新」提示需要：先 `PUT` 修正一条法条 → 再看引用它的旧会话 → 旧 `lawItemId` 的 `status` 变 `amended`。该场景留给 Lead 在 §八 验收。

## 五、导出实现

- `exportAiConversation(id)`：`responseType: 'blob'`，timeout 60s。
- 浏览器侧：
  1. 取 `Blob`；
  2. `blob.text()` 解析文件 JSON，读 `truncated`（服务端 >200 条截断标记）；
  3. 用 `URL.createObjectURL` + `<a download>` 触发下载，文件名按 E3 规范前端拼 `AI-CONV-<id>-<yyyyMMddHHmm>.json`（用 `Intl.DateTimeFormat` 固定 `Asia/Shanghai`）；
  4. `truncated=true` 时 `ElMessage.warning('该会话消息超过 200 条，导出内容已截断')`，否则 success。
- **审计**：导出动作由服务端写 `operation_log(action=AI_CONVERSATION_EXPORT)` 并回写 `is_exported/export_urls`，前端不写任何上报（AGENTS §10 要求服务端 AOP 采集）。
- 未验证：真实点击下载（CDP 下载行为、`Content-Disposition` 文件名、脱敏结果、`operation_log` 落库）——见 §七/§八。
