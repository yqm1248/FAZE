## 二、前端消费的接口契约（5 个，与后端对齐后的定稿）

| # | 方法与路径（前端写相对路径，由 `/biz-api` 前缀拼） | 说明 |
|---|---|---|
| 1 | `GET /api/v1/admin/law-items?lawCode=&articleNo=&kw=&isEnabled=&pageNum=&pageSize=` | 列表，RuoYi `TableDataInfo`（顶层 `code/msg/rows/total`）。行字段：`id, lawCode, lawName, articleNo, articleSeq, contentSummary, effectiveDate, expireDate, status, isEnabled, keywords, createdAt, updatedAt, aiRefCount`。`isEnabled` 不传=只看启用；传 0=只看已停用 |
| 2 | `GET /api/v1/admin/law-items/{id}` | 详情 `R<data>`：列表字段 + 全文 `content` + `createdBy/createdByType`；**amended / 已停用旧行也能按 id 查**（A-28 的快照对比依赖这点） |
| 3 | `PUT /api/v1/admin/law-items/{id}` | 修正 = 写新版本。body `{content(必填), effectiveDate(必填 yyyy-MM-dd), keywords?}`；后端同事务把旧行置 `amended/is_enabled=0` 并 INSERT 新 active 行 |
| 4 | `POST /api/v1/admin/law-items/import` | `multipart/form-data`（文件字段名 **`file`**）或 `application/json` 顶层数组；返回 `R<{total, inserted, skipped, failed:[{index,reason}]}>`，`index` 从 0 开始；幂等键 `(lawCode, articleNo, effectiveDate)` |
| 5 | `POST /api/v1/admin/law-items/{id}/disable` | 标记失效（不物理删除），`R<Void>`；重复调用幂等 |

> 列表**不返回全文**，只返回 `contentSummary`（≤200 字）；全文只在「查看/修正」弹窗里按 id 拉详情。这条是与后端对齐过的（避免列表里把摘要当全文展示）。

### 3.5 操作与弹窗
- **查看**：按 id 拉详情，`el-descriptions` 展示法律/代码/条号/效力状态/生效/失效/AI 引用次数/录入人类型/创建更新时间/关键词，下面「条文全文」块（`pre-wrap`、可滚动）。amended 旧行额外提示「已由新版本替代，历史快照不回改」。
- **修正**：`el-dialog` 表单 = 法律/条号（只读）+ 修正生效日（date-picker，必填，且前端先拦「不晚于旧版本生效日」）+ 关键词 + 条文全文（必填，预填详情全文）。弹窗顶部警告「修正不会覆盖旧条文：旧版本标记为已修正并失效，同时新增一条新版本；AI 历史快照不回溯改写」。提交后重拉列表。
- **标记失效**：`ElMessageBox.confirm` 二次确认，文案明确「记录保留、不物理删除、历史快照不改写、列表默认不再显示」，确认后 `POST /{id}/disable` 并刷新。
- **批量导入**（`import-dialog.vue`）：
  - 两种入参：上传 `.json`（前端校验扩展名 + ≤5MB，multipart 文件字段 `file`）/ 直接粘贴 JSON 数组（前端先 `JSON.parse` + 数组 + ≤500 条 + 必填字段 `lawCode/lawName/articleNo/content/effectiveDate` + 日期格式预校验，最多列 10 处问题）。
  - 弹窗顶部说明幂等键与 500 条上限；JSON 示例放在可横向滚动的代码块里，不再把长 JSON 塞进正文导致断词。
  - 结果面板：`total / inserted / skipped / failed.length` 四个数字 + failed 明细表（`第 N 条` = `index + 1`，同时保留原始 `index`），并提示「导入是同步写库，关闭后列表立即可见」。
  - 成功（inserted > 0）后向父页 `emit('success')` → 父页回第一页重拉列表。

### 3.6 四态
- 加载中：表格 `v-loading`；
- 空：`el-empty`，区分「无筛选无数据 → 可批量导入」「筛选无结果」「已停用无结果」；
- 错误：常驻 `el-alert` + 重试按钮；404 文案走 `describeRequestError`（「接口不存在（HTTP 404）：后端该接口可能尚未实现，或 faze-api 未启动」），不把 axios 英文原生串直接甩给运营；
- 正常：表格 + 分页（10/20/50）。

### 6.2 一条容易被误读的现象

`aiRefCount` 按 `law_item_id` 统计。**修正法条后，历史引用留在旧行，新行计数为 0**——这是「引用快照按 law_item 记录」的设计使然（工作流 L922 与 H2 的「快照永不回改」都要求如此），不是 bug。A-27 列表默认只显示新行，所以运营会看到「引用次数变 0」，需要知道这是版本切换的正常表现。

### 6.3 验收中发现并修掉的 3 个边界缺陷（Lead 发现 → be-ai-admin 修 → Lead 复测）

第一次打真接口时，第 10 项暴露出三个问题。**都是真实缺陷，不是测试方法问题**：

| # | 缺陷 | 根因 | 修法 | 复测结果 |
|---|---|---|---|---|
| 1 | `application/json` 的导入 body 没有 5MB 上限（8.6MB 照单全收） | `spring.servlet.multipart.max-request-size` 只约束 multipart，**不约束普通 JSON body** | 控制器入口读 `Content-Length`，>5MB 直接回 401001（不进反序列化）；上限常量与 multipart 共用 | ✅ `401001「导入内容超过 5MB（当前 8.6 MB），请分批导入（单次最多 500 条）」`，未写库 |
| 2 | multipart 超 5MB 报 `501001 服务器内部错误` | `MaxUploadSizeExceededException` 被 GlobalExceptionHandler 的兜底分支吃掉 | 新增 `MaxUploadSizeExceededException` 与 `MultipartException` 两条 handler → 401001 + 可读文案 | ✅ `401001「上传文件超过 5MB 上限」` |
| 3 | 单条 `content` 无长度上限（实测写进过 30000 字） | 导入/修正都没有 per-item 长度校验 | 导入侧 5000 字 → 归入 `failed[{index,reason}]`（不整体拒绝）；修正侧 `@Size(max=5000)`（单对象请求，整请求报错语义合适） | ✅ 见第六节第 11 行 |

**一处实现与 Lead 原方案不同、但更合理的处理（已采纳）**：缺陷 1 的报错没有用 `throw BusinessException(...)`，而是 `R.fail(ErrorCode, 可读文案)`。原因：按《后端代码规范》与 `GlobalExceptionHandler` 的既有实现，`BusinessException.detail` **只进日志不进响应体**，抛异常客户端只会看到「参数校验失败」，达不到「msg 里写清当前几 MB」的目的。`R.fail(code, detail)` 是本项目给「参数校验字段级提示」准备的既有出口，不新增错误码、不改全局行为。

**残留边界（如实记录）**：缺陷 1 只认 `Content-Length` 头；HTTP chunked 分块上传（无该头）无法预检，会走到正常解析流程。浏览器与 axios 一定会带该头，curl 默认也带；要彻底堵住需 Servlet 级 `Filter` 限流，本段没做。
