## 二、五家商店的差异要求（2026-11 时的口径，提交前按各后台最新要求核）

| 商店 | 包名后缀要求 | 备案要求 | 特殊材料 |
|---|---|---|---|
| 华为应用市场 | 无 | **强制**：App 备案号（工信部） | 需《计算机软件著作权登记证书》或授权书；隐私政策须可访问 |
| 小米应用商店 | 无 | **强制** | 需开发者实名认证；金融/法律类需额外资质说明 |
| OPPO 软件商店 | 无 | **强制** | 需「法律咨询」类目资质说明（平台模板） |
| vivo 应用商店 | 无 | **强制** | 同上；另需未成年人保护承诺函 |
| 应用宝（腾讯） | 无 | **强制** | 需软著；隐私政策检测（腾讯自检工具会扫权限清单） |

**共性结论**：五家**全部**要求 App 备案号与可访问的隐私政策。这两项一项未到位就全部提交不了。
所以 `8-A9` 的"提交"动作**只能等 DEF-004 + DEF-008 落地后**，不是技术侧排期问题。

## 四、等外部到位后，按这个顺序做（别乱序，会白跑）

1. **先拿备案号与软著**（没有它们，后面每一步都可能被驳回，包括内部测试包）；
2. 出正式图标与启动图（1024×1024 主图 + Android adaptive icon 前景/背景 + iOS 各尺寸）；
3. 用**真机**截图：四语言 × 首页 / 找律师 / 下单 / 聊天 / 我的，共 20 张（商店一般要 3~5 张/语言，
   建议每语言 4 张）；
4. 部署隐私政策与用户协议的可公开访问页面（当前正文在 `sys_config`，需要挂到一个真实域名）；
5. 统一版本号（`app.config.ts` 与 `sys_config.app.version.latest`）；
6. 生成 keystore 并存入 EAS 凭据（**只存一份在安全处，丢了不能更新**）；
7. 各商店后台按第二节逐项提交；**先提交一家的内部测试轨道**，通过后再铺其余四家；
8. 提交结果回写 `docs/CHANGELOG.md` 与本节（`8-A9` 只有在**真的提交了**之后才能改判「完成」）。

## 五、这份清单不是什么

- **不是"材料齐备"的证明**：15 项里 6 项❌、4 项⚠️、5 项✅，硬阻塞 2 项（备案号、图标）；
- **不是最新商店政策**：各商店要求每季度会变，提交前按各后台的现行要求重核一遍；
- **不代表 `8-A9` 通过**：`8-A9` 的通过标准是「五家商店材料全部齐备**并已提交**」，
  本文只做到"清点"，没做到"提交"。
