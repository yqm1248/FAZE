## 四、已知问题与口径限制

1. **长度膨胀是普遍现象，不是错误**。脚本的「膨胀>3」列数字很大（`profile` 每语言 212~248 条、`trade` 约 202 条），原因是阿拉伯字母/藏文表达同一含义所需的**字符数**普遍是中文的 1.5~3 倍。
   - 这个数字**只能当 `8-A1` 逐页走查的重点名单**，不能当质量判据。
   - 走查时必须看真实 UI：藏文断行（tsheg）、维/哈 RTL 混排下数字方向。
2. **术语一致性未自动校验**。51 条法律术语的目标语言写法靠人工保持（本次以 `error.json`、`document.json`、`workbench.json` 的既有译法为基准对齐，如「送达」「签收」「文书」「证据」「律师」）。脚本没有做「同义词变体」检测。
3. **无母语者校对**。按负责人 2026-11-09 口径 **C（不签、挂账）**，本批译文质量无人工担保；上线后若出现术语错误由平台承担。此条已写入段 8 挂账。
4. **`error.json` 的 key 是完整 msgKey**，翻译时 key 原样保留、只翻值，已校验无前缀增删。
5. **法律专名属自造构词**（无官方藏文/维文/哈文法律术语表可对照）：`case.json` 的「原告/被告/案号/立案」等是按字面构词写的（如 bo `ཞུ་སྦྱོར་མཁན` / `ལན་སྤྲོད་མཁན`，ug `دەۋاگەر` / `جاۋابكار`，kk `داعۋاگەر` / `جاۋاپكەر`）。**这一条优先交给母语法律人校对**，勿按原文当权威。
6. **本次产出不改变运行行为**：`shared/i18n/index.ts` 目前只加载 `zh-Hans`，bo/ug/kk 的 JSON 即便放进 `resources/` 也不会生效，还需要一次代码接线（把三语 import 进 `resources/index.ts` 并让 `t()` 按当前语言查表）。这是段 8 的另一项独立工作，不在本次翻译范围内。
