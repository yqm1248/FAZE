# `5-A1` 在线立案

> 段 5 验收锚点。采集：2026-11-08，`faze-api` 8081（dev）+ MySQL `faze`。
> 证据来源：B 组冒烟（`PROGRESS-A-B.md` §三）+ 本轮补测 PC 抽屉逐字段。

## 1. 结论

**通过**（判据 5/5 命中）。唯一瑕疵是**测试数据的中文变成 `????`** —— 建案时用 PowerShell 控制台传 curl，中文被 GBK 控制台吞掉后写进库，属数据问题不是代码问题（见 §4）。

## 2. 判据

| # | 要求 | 实测 |
|---|---|---|
| 1 | 案件编号匹配 `^CS\d{14}$` | `CS20261108000004` ✅ |
| 2 | `form_snapshot` 非空且含四步全部字段 | 9 个键：`caseType` / `disputeType` / `location` / `plaintiff{name,phone,idCard}` / `defendant{name,address}` / `statement` / `claims` / `amountCents` / `evidenceUrls` ✅ |
| 3 | PC 抽屉能看到**每个字段的值**（不是只显示字段名） | `GET /admin/cases/1` 返回 `formSnapshot` 原文，JSON 里逐字段有值（金额 `5000000`、身份证 `110101199001011234`、电话 `13900000001`）✅ |
| 4 | 审核通过后 APP 状态变「立案中」 | `POST /admin/cases/1/audit {approve}` → `legal_case.status = accepted` ✅ |
| 5 | `case_progress` 有 2 条（提交 + 审核通过） | `step1 submitted/user` + `step2 accepted/admin` ✅（后续 A2 测试又追加了 2 条） |

## 3. 幂等

同一 `Idempotency-Key` 重复提交只产生 1 条案件（`PROGRESS-A-B.md` §三：`idem same=True caseNo=CS20261108000004`）。

## 4. 已知数据瑕疵（不是代码缺陷）

`formSnapshot` 里的中文全是 `????`：建案时用 PowerShell 单行 curl 传 body，控制台按 GBK 编码把 UTF-8 中文替换成了问号，**入库的就是问号**。
- 影响：PC 抽屉能看到字段结构，但中文值不可读；
- 处置：不作为代码缺陷；需要干净数据时用 `--data-binary @file` 以 UTF-8 文件传参重建一单（本轮 A2 的测试案件即用文件传参，中文正常）。
