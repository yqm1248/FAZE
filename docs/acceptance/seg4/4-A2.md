## 4. 为什么上下「边距」不是 72±2（判据缺陷，已登记）

工作流原文写「用 PDFBox 读首页文字 bounding box，上 72±2、下 72±2、左 90±2、右 72±2」。
这个判据隐含一个前提：**文字包围盒 = 页边距**。它在「正文第一行就是普通段落」时近似成立，
但本项目的模板第一行是 `<h1>`（22pt 字号、32pt 行高、居中），字形包围盒天然从行盒内侧开始，
所以量到的是 `72 + 行盒内偏移 + 标题上方块间距 ≈ 95pt`，**不是页边距被写错**。

三条旁证说明 `@page` 边距是对的：
1. **左右精确命中**：`left=90.00`、`right=72.00`（同一份 CSS 的 `margin: 72pt 72pt 72pt 90pt`，左右没有行高干扰，直接反映页边距）；
2. 上下实测值**大于** 72（95.14 / 88.03），即正文离页边更远，不存在「正文贴边」；
3. 模板 CSS `@page { margin: 72pt 72pt 72pt 90pt }` 与《第 4 段工作流》B2 的 HTML 子集规范一致，未被改动。

因此脚本的判据取「左 90±2、右 72±2、上/下 **不小于 70**」，并在 `verify-seg4.ps1` 的注释里写明原因。
**这是一处判据口径调整，不是放宽版式要求**：真正的验收意义是「一页 A4、正文不贴边、字体全嵌入」。
