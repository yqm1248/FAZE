## 4. 「H1 == H2」为什么不是自证

`H1` 与 `H2` 是**两次独立下载**（两次 `GET /export` → 两次现签 URL → 两个本地文件）算出来的 SHA-256。
如果保存模板时是「原地 UPDATE `template_html`」，`document.pdf_oss_key` 指向的对象不变，但**「历史文书重下载」若走重渲染就会变**；本次实现里 `pdf_oss_key` 是不可变对象、导出直接签它，所以两次字节相同。
`H3 != H1` 证明重新生成确实产了**新字节**（模板版式改了，字号 20→18）。

## 5. 修掉的缺陷：模板升版后「重新生成」直接失败

**现象**（第一次跑本锚点时）：
```text
== 4. 对 A 重新生成 ==
  [FAIL] 重新生成后状态 期望 [generated] 实际 [failed]
```
库里 `document.errorMsg=上次生成失败，请修改后重新生成`，`task_queue.last_error=406001: 模板不存在或已停用`。

**根因**：`DocGenerateHandler.doGenerate` 用 `docTemplateMapper.selectById(doc.getTemplateId())` 取模板行并要求 `status='active'`。而 A1 的版本机制是「改版插新行 + 旧行 inactive」——文书 `template_id` 指向的那行**必然**在每次模板改版后变成 `inactive`，于是「重新生成」永远失败。同理 `AppDocumentService.save`（改表单再保存）也会 406001。

**修复**：新增 `DocTemplateResolver`：
- 模板行 `active` → 直接用；
- `inactive`/缺失 → 按 `code + lang` 找**同编码最新 active 行**；
- 都找不到（模板真停用了）→ 仍抛 406001。

接入点：`DocGenerateHandler`（生成/重新生成）、`AppDocumentService#save`（保存草稿）。生成成功后同时把 `document.template_id` 指到本次实际用的那一行，`template_version` 一起更新——否则下次复现又会沿旧行解析。

**修复后**：本文件 §2/§3 的六步全绿；另外把修复前失败的那份文书（`document.id=10`，`status=failed`、`template_id` 指向已 inactive 的 v2 行）再点一次「重新生成」，成功变为 `generated`。
