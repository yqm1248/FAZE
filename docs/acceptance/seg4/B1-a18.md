## 二、验收中发现并修复的 3 个缺陷

### 2.1 菜单 id 冲突：会覆盖段 3 的法条库菜单（严重）

`seg4_admin_menu.sql` 原稿声称「2201~2205 是段 3 留的空号」，实际段 3 用满了 `2200`~`2209`
（`2201` 法条库 / `2202`~`2205` 法条按钮 / `2206` 系统设置 / `2207` AI 对话检索 / `2208`~`2209` 按钮）。
直接执行会把这 5 条**覆盖成文书模板相关菜单**。

修复：改用 `2210`/`2211`（执行前已查 `SELECT MAX(menu_id)` = 2209）。
修复后复查段 3 的 10 条菜单完好。

### 2.2 编辑页路由根本不存在（严重）

原稿把「模板编辑」挂在「文书模板」（菜单 C 类型）下面。RuoYi `SysMenuServiceImpl.buildMenus`
第 186 行只在 `menu_type='M'`（目录）时展开 children，**C 下挂 C 的子菜单被直接丢弃**。
表现：`getRouters` 里 `/content/template` 的 children 只有自己，没有编辑页；点「新建模板」跳到
`/biz/document/template/edit/new` → **404**。

修复（照段 1 的 `content/article/edit` 先例）：
- 菜单 2211 改为挂在目录 2200 下，`path = template/edit/:id`；
- 补 `route_name`：`DocTemplate` / `DocTemplateEdit`（否则 name 是 `Template/edit/:id`，含 `/` 和 `:`）；
- 前端跳转路径由 `/biz/document/template/...` 改为真实路由 `/content/template/...`。

修复后 `getRouters` 返回：
```
/content → children: [ template, law-library, template/edit/:id (hidden) ]
```

### 2.3 列表页三处显示问题

| 问题 | 原因 | 修复 |
|---|---|---|
| 更新时间显示 `2026-11-07T11:5`（被切） | 后端 ISO 带 `T` 直接渲染 + 操作列 `fixed="right"` 遮挡 | 用 RuoYi `parseTime` 格式化为 `YYYY-MM-DD HH:mm:ss` |
| 编码 `CROSSBORDE...` 截断 | 列宽 140 不够放 `CROSSBORDER-001` | 编码列 min-width 140→160，名称 180→170 |
| 保存后列表出现两行同名模板 | `list()` 无版本过滤，v1(inactive) 也被列出 | 加 `NOT EXISTS (... t2.version > t.version)`，只列每个 `(code, lang)` 最新版 |

> 旧版本行按锚点 `4-A4` 要求**继续保留在库里**（供历史文书重渲染），只是不进管理列表——
> 否则运营点旧版本编辑会基于旧 HTML 生成 v3，内容回退。

## 五、A-18 第 7 项：预览缓存复用（本次新增）

`DocTemplateAdminService.preview()` 增加：若该版本行已有 `preview_oss_key`，直接返回签名 URL，
不再重新渲染。安全性前提：**版本行不可变**（保存总是 INSERT 新行，旧行永不改 HTML）。

实测（模板 id=6，首次预览时 `preview_oss_key` 为 NULL）：

| 调用 | 返回 key | `doc_template.updated_at` |
|---|---|---|
| 第 1 次 | `private/doc_template/202611/0/4b1795f6-...png` | `2026-11-07 12:37:06`（写入） |
| 第 2 次 | **同一个 key** | **仍是 `12:37:06`**（没回写） |

第 2 次 URL 的 `exp`/`sig` 不同是预期（每次重新签名），`key` 相同且 `updated_at` 未变，
证明**没有重新渲染、没有 `updateById`**。
