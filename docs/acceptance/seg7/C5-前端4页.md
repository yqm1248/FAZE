## 六、偏离登记（已写入《第 7 段工作流》§十一）

1. **工作流写「留言复用 58 页 `type=service`」不可行**：后端 `FeedbackSubmitBO.type` 白名单只有
   `feature/bug/experience/other`，无 `service`。改为 `type=other` + `?from=support` 换引导文案。
2. **55 页「大家常问」按 `sortOrder` 取前 5，不是「按点击量」**：`faq` 表没有点击量字段。
3. **截图上传 `WebFileButton` 只在 Web 生效**：Expo 依赖里没有 `expo-image-picker`，
   原生端点「选填，最多 3 张」无反应。与本段「浏览器验收」口径一致，接原生时替换组件。
4. **55 页电话入口用主色浅底 + 橙色图标**：令牌层没有 `state.warningSoft`，新增它要同步
   `tokens.json` / `设计令牌.md` 并重算基线指纹，为一个图标底色不做。
5. **新增后端上传 scene `complaint` / `feedback`**：C5 截图需要，属存储层白名单扩充。
   **原记录「前后端 `ALLOWED_SCENES` 与 `UploadScene` 已同步」不准确**：只改了
   `StorageKeyRules.ALLOWED_SCENES` 与 APP 侧 `UploadScene`，**漏了 `UploadBO` 的 Bean Validation
   正则**，而那是入参的第一道闸——结果是场景白名单「看起来加了、实际进不去」。
   2026-11-09 修复并补了回归测试 `UploadBOTest`（4 个断言，钉住三处一致）。
   这类「同一份白名单存在多处、改一处漏一处」的缺陷，本段一共出现过两次
   （另一次是 `content_review.biz_id=0`），已在 §十一 记为通用教训。
6. **`app_user.region` 已建列但无采集点**：恒为 NULL；地区分布只返回一项「其他」、
   按地区发送必然 0 人。采集入口段 8 补（详见 §十一 第 11 条）。

## 七、复现命令

```powershell
# 后端（8081，别用 8080/8090）
cd deploy; .\restart-api.ps1

# 前端：必须显式指定 8090 —— expo 默认抢 8081，会顶掉 faze-api
cd apps\mobile-app; npx expo start --web --port 8090

# 截图（CDP，真实 Chrome，390×844）
cd ..\..
node scripts/cdp-shot.mjs --url http://localhost:8090/support --out tmp/seg7/c5-55-support.png --width 390 --height 844 --mobile --wait 9000
```

> **踩过的坑**：`expo start --web` 默认端口 = 8081，与 `FAZE_API_PORT` 相同。
> 它不会报「端口被占用」，而是**静默抢占**，导致 faze-api 起不来、前端所有请求打到 Metro 返回 HTML。
> 另：`deploy/restart-api.ps1` 只等「端口可连接」就报 ready，端口被别的东西占着时会**假阳性**（已记 §十一）。
