```text
{"msgtype":"markdown","markdown":{"title":"[P1] FazeHighErrorRate",

```

### 4.2 恢复通知（resolved）

把 mock 的告警状态切成 `resolved` 后，下一轮自动发出：

```text
[2026-11-09T02:01:57+08:00] POST /dingtalk  body_bytes=194
{"msgtype":"markdown","markdown":{"title":"✅ 已恢复：FazeHighErrorRate",
 "text":"#### ✅ 已恢复：FazeHighErrorRate\n> **时间**：2026-11-09 02:01:57\n> **环境**：本机开发\n"}}
```

- 去重：`faze:alert:sent:{alertName}:{fingerprint}` SETNX TTL 1h（firing 只发一次，实测 mock 日志 `received #3` 只有一条 firing）。
- **修复**：webhook 为空时**先返回、不写去重 key**（旧实现先 SETNX 再判空，配好 webhook 后要等 1 小时 TTL 才发第一条，
  演练时表现为「配好了却一直没消息」）。
- 加签：`timestamp+"\n"+secret` → HmacSHA256 → Base64 → `&timestamp=&sign=`（本次 secret 为空，走无签路径；
  T4 配 secret 后自动生效，无需改代码）。
- 演练后已恢复 `alert.prometheus_url=http://127.0.0.1:9090`；`alert.dingtalk_webhook` 保留指向本机 mock（便于 H3 复验）。

## 7. 偏差与降级（Lead 要写 §十一）

1. **`management.server.address: 127.0.0.1` 无法落地**：SB4 在 actuator 与业务同端口时禁止配置该键
   （启动即 `IllegalStateException`，43 个测试上下文全部加载失败）。去掉该键；「不裸奔」改由
   `SecurityConfig` 保证：`/actuator/**` 本机（127.0.0.1 / ::1）免鉴权、非本机要求 `ROLE_ADMIN`，
   且只 expose 4 个端点（`env`/`heapdump` 未暴露 → 404）。要真正「只绑本机」必须给 management 开独立端口，
   但会破坏 T4 的 `127.0.0.1:8081/actuator/prometheus` 抓取约定，故**不采用**。
2. **`logstash-logback-encoder:8.1` 显式锁版本**：不在 Spring Boot BOM 里；8.1 要求 logback 1.5.x（SB4 自带满足）。
   升级 logback 前需重验兼容性。
3. **异步导出（>5000 行）未做 curl 级 6000 行实测**：需要往日志表灌 6000 行，且 `operation_log` 无 DELETE 权限
   （不可清理，会污染审计证据链）。改用 `ExportServiceTest` 固化边界（入队/taskId/落文件/下载/过期/非法 taskId），
   并保留 `FAZE_EXPORT_SYNC_MAX_ROWS` 环境变量便于复验（设 5 即让任意非空导出走异步）。
4. **管理员站内通知发不了**：`notification.user_id` 指向 `app_user`，管理员在 `faze_admin.sys_user`。
   异步导出完成只落文件 + INFO 日志（工作流允许的降级出口）。
5. **`targetDisplay` 未覆盖全部 28 种 target_type**：白名单外类型仍显示 `类型#id`。已覆盖 T3/Lead 点名的
   全部高频类型；其余（提现单/案例/送达/结算/文书模板等）按「映射不到就 type#id」处理，不做通用反射。
6. **`article` 表无作者字段**：关注列表的 `feedType=article` 分支当前不会产出（只有 `reply` 与 `none`），
   数据缺口，记 §十一；段 8 补文章作者后启用。
7. **`social_action.target_type` 库值是 `case_library`，对外契约是 `case`**：接口层做双向映射，不改已有数据。
8. **`GET /app/social/favorites` 的列表只含仍可见目标**：收藏 3 篇文章（2 篇 `archived`）实测列表 1 条、counts=3。
   这是设计（VO 注释第 3 条），若验收要求「列表条数 = counts」需另行拍板。
9. **新增依赖未登记 `docs/architecture/依赖清单.md`**：该文档属 T5 作用域（我不许改），请 Lead 转交登记：
   `spring-boot-starter-actuator`、`micrometer-registry-prometheus`、`net.logstash.logback:logstash-logback-encoder:8.1`。
10. **重启方式**：`deploy/restart-api.ps1` 在「后台 job 结束」时会连带杀掉被它启动的 java 进程树
    （实测两次：job 状态 completed 后 8081 变不可达，java 进程消失）。最后用
    `deploy/start-api.ps1` 前台启动（超时转后台 job 并保持运行）才稳定。
