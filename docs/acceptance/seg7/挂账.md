## 二、功能/结构缺陷挂账

### 1. 告警通道三条硬缺口（`7-A8` 的核心）

1. ~~**`FazeServiceDown` 永远推不出去**~~ → ✅ **已修（2026-11-09）**：`AlertDispatcher` 是 `@Scheduled`、
   跑在 faze-api 进程内，服务一挂派发器自己也不跑。**解法不是挪派发器，而是加一条进程外的路**：
   新增 `scripts/monitor/health-probe.ps1`（计划任务每 1 分钟跑，连续 2 次失败判定服务已挂，
   自己直接 POST 钉钉，30 分钟去重 + 恢复通知 + 日志 5MB 轮转 + `-DryRun`）。
   配套 `install-health-probe-task.ps1`（默认只打印命令、`-Apply` 才执行、`-Uninstall` 支持）+ `alert-config.json`。
   **实测**：DryRun 正常路径 exit 0；不可达路径连败 2 次 → 打印 `[P0]` JSON 且不写状态文件；
   真实发送用 mock 8088 验过 firing/去重/恢复三条（595B P0 告警、第 2 轮命中 30 分钟去重、恢复轮 exit 5）。
   **本机计划任务未注册**（按要求不动系统配置），命令见《运维手册》§3.7.3。
2. ~~**恢复通知在真实 Prometheus 下是死代码**~~ → ✅ **已修（2026-11-09，方案 B 差集）**。原判断「改读 `/api/v1/rules` 的 `alerts[].state`」经复核**同样拿不到恢复**——`/api/v1/rules` 的 `alerts[]` 只装活跃告警，`inactive` 的通常不出现。实际改法：每轮把当前 firing 的 `{alertName}|{fingerprint}` 写 Redis `faze:alert:last-firing`（TTL 1 天），**上一轮有、本轮没有 = 已恢复**；查询失败时**不动集合**（防网络抖动刷假恢复）。
   **实测**：mock Prometheus(9091) firing → `03:34:06` 收到 `[P1] FazeHighErrorRate`；让其消失 → `03:35:06` 收到 `✅ 已恢复：FazeHighErrorRate`，日志「本轮新推 firing=0 resolved=1」；另附验「查询失败不误判恢复」（9090 停时未发任何恢复）。
3. ~~**去重键「先写后发」会吞告警**~~ → ✅ **已修（2026-11-09）**：改为发送前只 `hasKey` 检查、**发送成功后才写** sentKey(TTL 1h)；失败不写 → 下轮重试。
   **实测**：webhook 指向不可达 `127.0.0.1:1` → `03:37:06` 发送失败、`EXISTS sentKey = 0`（未占窗口）；恢复 webhook 后 `03:38:06` 重发成功、`EXISTS = 1`。代价是两个实例可能各发一次（**重复而非漏**，与既有「Redis 故障按未发送处理」同一原则）。
4. **真实钉钉群未配**（**仍未解决，需负责人**）：`sys_config.alert.dingtalk_webhook` 当前是 `http://127.0.0.1:8088/dingtalk`（演练 mock），`alert.dingtalk_secret` 为空串，进程外探活的 `alert-config.json` 里 webhook 也留空。**换真地址前不要当成「已配置」**；真实地址请放 `deploy/.env` 的 `FAZE_ALERT_WEBHOOK`（已 gitignore）。

### 2. 错误码与环境

5. **错误率口径** → ✅ **已定（2026-11-09 负责人拍板选 A）**：**按业务错误码统计**（`code != 200` 占比），**不**改成真返 5xx（`R<T>` 是对外契约）。已交给 be-api 落地：新增业务错误指标 + 改 `FazeHighErrorRate` 表达式，阈值仍取 `sys_config.alert.error_rate_pct`。原文留档：`GlobalExceptionHandler` 把所有 `RuntimeException` 映射成 HTTP 200 + 业务码，`status="500"` 恒 0，`FazeHighErrorRate` 在生产永不 firing；本批加了 dev-only `/api/v1/dev/fault`（`@Profile("!prod")`）仅供演练。
6. **`management.server.address` 落不了地**：SB4 同端口配该键**启动即失败**（43 个 `@SpringBootTest` 全挂）。现在靠 `SecurityConfig`「本机来源 OR ROLE_ADMIN」+ 只 expose 4 个端点保证不裸奔（实测 `/actuator/env`=404）。**生产部署时必须重评**（给 management 独立端口）。
