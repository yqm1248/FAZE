  该口径冲突已记入 §十一 偏差清单。

──── 与工作流文档的偏差（3 条，全部记入 §十一）─────────────────────────
1. 类名：文档要求产出 `RechargeService` / `RechargeServiceImpl`，但该名字已被段 1 D4 的
   「手工充值/调账」服务占用（modules/trade/service/RechargeService.java，已验收）。
   本段实现为 `RechargeOrderService`（App 充值单）+ `RechargeCreateExecutor`（事务落单）。
   不合并、不复用：手工充值是管理端后台入账，线上充值是渠道回调入账，事务边界与幂等口径不同。
2. Swagger：文档「算做完」要求「Swagger 列出 3 个接口」，但本项目 pom 无 springdoc/knife4j 依赖
   （段 0~5 均未接入），`/v3/api-docs` 返回 401。本段不擅自引入新依赖（需登记依赖清单 + 评审），
   改用「直接调通 3 个路由」作为证据。若负责人要 Swagger，属新需求，记入 §十。
3. 金额 999 分判据旧口径，见验收项 C 的说明。

──── 本轮未做（按分组顺序留给后续任务）───────────────────────────────
1. 「本地 pending 且距下单超过 5 秒就现查渠道」的**入账部分**：本轮只调 gateway.query() 并记日志，

   入账能力在 C3 实现后接上，验收锚点 6-A3 在 D1 复验。
2. 单日限额的边界组合（10 笔 / 5000 元 / 关单后额度恢复）由 B3 的单测与证据覆盖。
