### B4 权限点的裁决（2026-11-08 负责人拍板）

**不做，改为停用 `ry` 演示账号。**

依据：B4 §8 要求 `finance:reconcile:list/handle` 权限点，但与三处已拍板决策冲突——
① 《接口规范》§6.2「只有一个管理员角色；`@PreAuthorize("hasRole('admin')")` 只校验角色，
不做数据级权限细分」；② 《开发计划总纲》§5.8 段 7 明确不做「多角色权限细分（只有管理员）」；
③ `AdminSession`「只有两个字段是故意的（接口规范 §1.3.1 第 4 条只取必要字段）」。
另：后台只有一个业务角色，权限点建起来**没有第二个角色可分配**；真正要做还需改
`AdminSessionStore` 用正则抽 RuoYi `LoginUser.permissions`（Java toString 格式，脆弱）。

替代动作已执行并验证：
```sql
UPDATE sys_user SET status='1', update_time=NOW() WHERE user_name='ry' AND status='0';
```
实测 `POST /login {"username":"ry","password":"admin123"}` → `code=500`、
`msg=用户已封禁，请联系管理员`、**无 token**；admin 仍可正常登录。
