# 目录与命名规范

## 1. 依赖方向（单向，违反即为设计错误）

```text
app/  ──────────────►  features/  ──────────────►  shared/
（薄路由壳）            （业务页面与私有组件）        （跨域复用与基础能力）
     │                                                 ▲
     └─────────────────────────────────────────────────┘
                     app/ 可以直接用 shared/ 的屏幕容器
```

规则：

1. `features/A` **不得** import `features/B`。跨域复用一律下沉到 `shared/`。
2. `shared/` **不得** import `features/`。基础层不认识业务。
3. `app/` 除页面导出外只允许 import `expo-router`、`shared/`、`features/*/pages/`。
4. `features/<domain>/pages` 可以 import 本域的 `components`、`types`、`__fixtures__`。

## 2. 应用端目录

```text
apps/mobile-app/
├─ app/                           Expo Router 路由壳；每个文件 1 行 export

│  ├─ (auth)/
│  │  ├─ _layout.tsx              认证流 Stack（无 tab）
│  │  ├─ login.tsx                → LoginPage
│  │  └─ register.tsx             → RegisterPage
│  ├─ (tabs)/
│  │  ├─ _layout.tsx              底部 5 tab 容器
│  │  ├─ index.tsx                → HomePage
│  │  ├─ lawyer.tsx               → LawyerListPage
│  │  ├─ agent.tsx                → AgentChatPage
│  │  ├─ case.tsx                 → CaseListPage
│  │  └─ profile.tsx              → ProfilePage
│  ├─ lawyer/

├─ features/
│  ├─ auth/                       {pages,components,__fixtures__,types.ts}
│  ├─ home/
│  ├─ lawyer/
│  ├─ agent/

│  ├─ profile/
```

## 3. 文件命名

| 类型 | 规则 | 示例 |
| --- | --- | --- |
| 页面组件 | 大驼峰 + `Page` | `LawyerDetailPage.tsx` |
| 业务组件 | 大驼峰 + 用途 | `LawyerCard.tsx`、`ProgressTimeline.tsx` |
| 共享组件 | 大驼峰 + 通用语义 | `Screen.tsx`、`AppCard.tsx` |
| 假数据 | 小驼峰 + `.fixture.ts` | `lawyers.fixture.ts` |
| 类型 | 小驼峰 + `.types.ts` | `lawyer.types.ts` 或域内 `types.ts` |
| 常量 | 小驼峰 + `.constants.ts` | `agent.constants.ts` |
| 路由壳 | 路由约定名（kebab-case） | `lawsuit-form.tsx`、`join.tsx` |
| Hook | `use` 开头小驼峰 | `useSplashRedirect.ts` |

禁止：`index.tsx` 承载页面实现（只能作为目录导出入口或 `(tabs)` 约定的路由文件）；
`utils2.ts`、`newPage.tsx`、`test.tsx` 等无语义命名。

## 4. 组件命名

- 组件名必须能读出"它渲染什么"，不得叫 `Item`、`Card2`、`Block`。
- 一个业务组件只服务一个页面时，放该 feature 的 `components/`；被两个域使用才进 `shared/`。
- 超过 200 行的组件文件必须拆分并说明拆分依据。

## 5. 路由约定

| 项 | 约定 |
| --- | --- |
| 路由路径 | 与 tab 名一致：`/`、`/lawyer`、`/agent`、`/case`、`/profile` |
| 详情页参数 | 用 `useLocalSearchParams` 取，参数名与原项目 URL 保持一致（`name`） |
| 认证流 | 放在 `(auth)` 分组，不显示 tab |
| 404 | `+not-found.tsx` 统一处理 |

## 6. 素材引用

原项目素材保留原始文件名（含空格，如 `if-group 2.png`）。**页面不得直接写路径字符串**，
必须通过 `assets/legacy/index.ts` 导出的常量：

```ts
import { LEGACY_IMAGES } from '@/assets/legacy';

<Image source={LEGACY_IMAGES.tabHome} />
```

这样素材替换或迁移只需改一处。
