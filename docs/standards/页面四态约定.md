# 页面四态约定（段 0 起生效，段 1~8 一律照此）

> **为什么要统一**：段 1 起会有 60+ 个页面需要异步数据。如果每页各写一套加载/空/错误，
> 结果必然是「有的页转圈、有的页白屏、有的页不显示错误原因」。四态做成通用组件之后，
> **页面只写正常态**，其余三态自动有。

代码位置：`apps/mobile-app/shared/components/async/`（`AsyncBoundary` / `LoadingState` / `EmptyState` / `ErrorState`）。

---

## 一、状态模型：四态，没有第五态

```ts
export type AsyncState<T> =
  | { phase: 'loading' }
  | { phase: 'empty' }
  | { phase: 'error'; error: AppError }
  | { phase: 'success'; data: T };
```

**为什么不设 `idle`**：`idle` 与 `loading` 在 UI 上无法区分（都是「还没有数据」），
多一个状态只会多一处「这里到底该显示什么」的争论。

## 二、`AsyncBoundary` 的用法

```tsx
const [state, setState] = useState<AsyncState<UserVO>>({ phase: 'loading' });

const load = async () => {
  setState({ phase: 'loading' });
  const result = await get<UserVO>('/api/v1/app/account/profile');
  if (!result.ok) { setState({ phase: 'error', error: result.error }); return; }
  setState(result.data === null ? { phase: 'empty' } : { phase: 'success', data: result.data });
};

<AsyncBoundary state={state} onRetry={load}>
  {(data) => <ProfileCard user={data} />}
</AsyncBoundary>
```

| 属性 | 语义 |
|---|---|
| `state` | 四态之一 |
| `onRetry` | **错误态**的「重试」回调，通常是重新发起请求的那个函数 |
| `children` | 正常态的渲染函数——**页面只写这一支** |
| `emptyHintKey` | 覆盖空态文案（可选） |
| `loadingRows` | 骨架屏行数（可选） |

## 三、错误文案映射（不许展示 `R.msg`）

| `AppError.kind` | 文案 key | 来源 |
|---|---|---|
| `network` | `error.common.network` | 断网、超时、DNS 失败 |
| `business` | `t(error.msgKey)` | 服务端返回的业务码对应的 msgKey |
| `parse` | `error.common.server` | 响应不是合法 JSON（例如被网关改写成 HTML） |

**`R.msg` 一律不展示**（接口规范 §5.1 约束 2）：它可能含 SQL、表名、类名。
`traceId` 有则用小字显示，便于后端定位，但**不作为主要信息**。

## 四、错误边界（`app/_layout.tsx` 的 `ErrorBoundary`）

- **只导出一处**：expo-router 约定从根布局导出 `ErrorBoundary`，它自动包住整棵路由树。
  再手写一个 `AppErrorBoundary` 会形成两个错误界面，验收时说不清看到的是哪一个。
- 边界界面必须做三件事：可读文案（不出现英文 `TypeError`）、`traceId`（有则显示）、
  **「重试」与「回登录页」两个出口**。
- **不做全局 `ErrorUtils.setGlobalHandler` 吞异常**：那会把崩溃变成白屏，`0-A8` 反而更难看。
- 边界内的文案必须能在 **i18n 未就绪**时工作，所以用硬编码中文常量（唯一允许两套文案的地方）。

## 五、`0-A8`（断网不崩）的三条硬约束

1. `shared/api/client.ts` 把网络异常归一成 `AppError{kind:'network'}`，**永不向渲染层抛异常**。
2. 所有异步调用走 `runAsync` 包装：有 `try/catch`，失败进 `error` 态；页面里禁止裸 `await`。
3. 首屏（`app/index.tsx`）读 SecureStore 失败也必须落到某个路由，**不许停在空白**。

## 六、禁止事项

1. 页面自己写 `ActivityIndicator` / 空态文案 / 错误弹窗——一律用四态组件。
2. 在 `error` 分支里展示 `error.msg` 原文。
3. 给「空态」加重试按钮（空态是成功，不是失败）。
4. 用 `ErrorUtils.setGlobalHandler` 把异常吞掉返回 `null`（=> 白屏）。
5. 在四态组件里发请求或管理状态（它们必须是纯展示，才能被任何数据源复用）。

## 七、验证方式

- `npx tsc --noEmit`：四态类型不匹配直接编译失败。
- 飞行模式冷启动：登录页显示错误态 + 重试；关飞行模式点重试能进正常态（`0-A8` 的验收动作）。
- `adb logcat *:E`：无 `FATAL EXCEPTION`。
