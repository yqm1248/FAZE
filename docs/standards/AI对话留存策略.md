# AI 对话留存策略 v1.0

> 适用：《第 3 段工作流》E3；`ai_conversation` / `ai_message` 两张表的全生命周期。
> 依据：《个人信息保护法》第 56 条；《审计与日志规范》§五；《技术路线》§16.2.1；《数据表规范》§9.2。
> 一句话：**AI 对话可能作为纠纷证据，所以存得久、原文不脱敏、日志里永不出现、删除只软删。**

---

## 一、五个必须回答的问题

| 问题 | 本段的答案 | 依据 |
|---|---|---|
| **存多久** | **1095 天（3 年）**，配置键 `sys_config.ai_message_retention_days=1095` | 《个人信息保护法》第 56 条「处理记录 ≥3 年」；《审计与日志规范》§五同类取值；负责人 2026-11-01 拍板定为 3 年 |
| **存储是否脱敏** | **不脱敏，原文完整落库** | 《技术路线》§16.2.1「原文完整落库，一个字不改」——AI 对话与聊天记录同性质，可能作为纠纷证据 |
| **展示是否脱敏** | **不脱敏**（限管理员权限内） | 与段 2 拍板第 7 项（IM 原文全量可见）一致；不一致会导致两个后台页两套口径 |
| **导出是否脱敏** | **脱敏**：手机号 `1[3-9]\d{9}` → `138****1234`；身份证保留前 3 后 2（`110***********34` 形式） | 导出文件离开系统管控范围，与段 2「禁止整包导出聊天记录」同一考虑 |
| **日志是否出现** | **永不出现**（L4 级敏感字段） | 《数据表规范》§9.2 把 `ai_message.content` 列为 L4；后端规范禁止把 L4 写进日志/错误上报/APM |

**「展示」与「导出」口径不同是有意的**：后台页面在系统内、有鉴权、有审计；导出文件一旦落地就可能被转发、被截图、被上传网盘。两者不能统一。

## 二、超期处理：本段不做自动清理

- **只留规则，不写代码**：清理必须走「**人工审批的运维脚本 + 先归档后删除**」，《审计与日志规范》§5.3 的同一模式。
- 理由：AI 对话是合规留痕证据，**自动删等于销毁证据**。任何自动清理任务都可能因为配置写错而在某天凌晨批量删除数据，且不可恢复。
- `ai_message_retention_days` 的值只供**运维脚本**读取与报表核对，**不驱动任何定时任务**。本段没有任何 `@Scheduled` 清理器——这一点在验收时要能断言（`grep` 不到清理任务）。

## 三、用户删除的语义（软删，不是物理删除）

| 动作 | 落库 | C 端列表（G1） | 后台 A-28（H2） |
|---|---|---|---|
| 用户删除会话 | `UPDATE ai_conversation SET deleted_at=UTC_TIMESTAMP()`；**`ai_message` 一行不动** | 不显示 | **仍能查到**，标「用户已删除」标签 |
| 用户不删、只是退出 | 无变化 | 显示 | 显示 |

- **设计稿 `03-agent.html` L268 的文案「也不会保留在『对话历史』里」是准确的**（只承诺列表不显示），**不许**改成「彻底删除」。
- 三处行为必须一致：本文档、G2（删除接口）、H2（后台检索）。任一处改成物理删除，另外两处都要跟着改口径——所以**先在本文档定死，代码按本文档写**。

## 四、导出格式（A-28 单条导出用）

- 格式：**JSON**（不做 PDF、不做 Word；PDF 属段 4 文书中心）
- 结构：

```json
{
  "conversation": {
    "id": "1234",
    "userId": "5678",
    "title": "借款不还怎么办",
    "lang": "zh-Hans",
    "createdAt": "2026-11-07T02:10:00Z",
    "deletedAt": null
  },
  "messages": [
    {
      "id": "9001",
      "role": "user",
      "content": "手机号 13812341234 的人借我钱不还……",
      "createdAt": "2026-11-07T02:10:00Z"
    },
    {
      "id": "9002",
      "role": "assistant",
      "content": "……（导出前已脱敏）……",
      "model": "doubao-seed-1.6-32k",
      "contentId": "AI-3f2a9c1e5b7d4a86b0c2e4d6f8a1b3c5",
      "refs": [ { "lawItemId": 679, "lawCode": "civil_code", "lawName": "中华人民共和国民法典", "articleNo": "第六百七十九条", "content": "……", "effectiveDate": "2021-01-01", "status": "active" } ],
      "createdAt": "2026-11-07T02:10:03Z"
    }
  ]
}
```

- **脱敏只作用于 `messages[].content` 与 `conversation.title`**（标题可能含手机号）。
- **`refs` 原样导出，不脱敏**：法条是公开信息，脱敏反而破坏可追溯性。
- 文件名：`AI-CONV-<conversationId>-<yyyyMMddHHmm>.json`（时间按 **Asia/Shanghai**）。
- 导出后回写：`ai_message.is_exported=1`、`ai_message.export_urls` 追加 `{"type":"json","url":"…","at":"…"}`。**只追加不覆盖**。

## 五、隐式标识的交接（本段只做服务端一半）

| 载体 | 谁做 | 要写什么 |
|---|---|---|
| JSON 导出 | **本段（H2）** | `messages[].contentId` 字段（已含） |
| PDF（段 4 文书中心） | 段 4 | 元数据 `Faze-Content-Id: {content_id}`，以及技术路线 §12.3.2 的另外 4 个字段 |
| 图片分享（段 7） | 段 7 | EXIF `AI-generated by 法泽 \| contentId: {content_id}` |

**本段只保证 `content_id` 存在且唯一**（`ai_message` 上的 `uk_ai_message_content_id`），不管它怎么被写进文件。写进文件的那一半由段 4 / 段 7 负责，不许在本段预埋假记录。
