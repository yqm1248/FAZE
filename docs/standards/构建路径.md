## 一、结论先行：走 EAS 云构建，不走本地

| 顺位 | 通道 | 结论 |
|---|---|---|
| ① | **EAS 云构建**（`preview` profile，`buildType: apk`） | ✅ **采用**。只依赖 Expo 账号 + 网络，不动本机环境 |
| ② | 本机装完整 Android SDK | 备选。约 10 GB 下载，且 RN 0.81 对 compileSdk/NDK 有版本对齐要求 |
| ③ | `expo-dev-client` 内测分发 | **不作验收载体**。dev-client 包启动要连 Metro，断网必然连不上，会污染 `0-A8`；它也不能证明「可安装」 |

**本机实测没有 Android SDK**：`ANDROID_HOME` / `ANDROID_SDK_ROOT` 均未设，`%LOCALAPPDATA%\Android\Sdk` 不存在；只有 winget 装的 `adb`。

## 二、首次构建做了什么（可复现的命令序列）

```powershell
# 0. 网络：EAS 需要走代理（本机直连超时）
$env:HTTPS_PROXY='http://127.0.0.1:7890'
$env:HTTP_PROXY=$env:HTTPS_PROXY

cd E:\dshcode\FAZE\apps\mobile-app

# 1. 确认登录态（本机已登录 1454132yqm）
npx --yes eas-cli@latest whoami

# 2. 建项目（只需一次）。注意必须带 --account：
#    该账号下有两个可创建项目的身份（个人 + team），不带会报「multiple accounts」
npx --yes eas-cli@latest init --account 1454132yqm --non-interactive
#    → 输出 projectId，手动写进 app.config.ts 的 extra.eas.projectId
#      （动态配置无法被 eas init 自动写入，这是 EAS 的已知限制）

# 3. 启动构建（--no-wait = 不跟踪进度，立刻拿到构建 URL）
npx --yes eas-cli@latest build --platform android --profile preview --non-interactive --no-wait
```

**首次构建会自动做一件事**：本机没有 `keytool`，EAS 在云端生成了 Android keystore（`√ Generating keystore in the cloud`）。keystore 由 EAS 托管，**永远不会入库**（`.gitignore` 已忽略 `*.jks`/`*.keystore`）。**不要换 keystore**——换了签名，手机上覆盖安装会 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`。

## 三、`eas.json` 三个 profile 的用途

| profile | 产物 | 用途 |
|---|---|---|
| `development` | APK（dev-client） | 现场调试、`adb logcat` 折腾。**不作为任何锚点的验收载体** |
| `preview` | **APK**（release 形态 JS bundle） | **`0-A1` / `0-A3` / `0-A5` / `0-A8` 的验收载体** |
| `production` | AAB | 段 0 不构建；只占位，避免段 8 有人拿 preview 的 APK 当上架产物 |

`buildType: "apk"` 是 internal distribution 出 APK 的关键键；不加会得到 `.aab`，手机装不上。

## 四、baseURL 是构建期内联的（最容易踩的坑）

`EXPO_PUBLIC_API_BASE_URL` 在 **构建时** 被内联进 JS bundle，**运行时改不了**。

- 当前写死在 `eas.json` 的 `build.preview.env` 里：`http://192.168.43.186:8081`
- **换网段（换 WiFi / 换电脑）就必须改这个值并重新构建**，否则 App 表现为「一直网络错误」
- 真机联调必须用 **PC 的局域网 IPv4**：不能用 `localhost`（指向手机自己）、不能用 `10.0.2.2`（Android 模拟器专用）
- Windows 防火墙要放行 8081
- **验收前置检查**：手机浏览器能打开 `http://<PC-IP>:8081/api/v1/pub/ping`

## 五、换机器重建的完整步骤

1. 装 Node（≥24）、npm（≥11）、Git。
2. `cd apps/mobile-app && npm ci`（**必须 `npm ci`**，不要 `npm install`；仓库只有 `package-lock.json`）。
3. 复制 `.env.example` 为 `.env`，填 `EXPO_PUBLIC_API_BASE_URL`（用那台机器的局域网 IP）。
4. 配代理（若网络受限）：`$env:HTTPS_PROXY` / `$env:HTTP_PROXY`。
5. `npx --yes eas-cli@latest login`（用项目负责人的 Expo 账号；如果换了账号，`eas init --account <新账号>` 会生成新 projectId，要同步改 `app.config.ts`）。
6. `npx --yes eas-cli@latest build --platform android --profile preview --non-interactive --no-wait`
7. 打开它打印的构建 URL，等状态变成 `finished`，下载 APK。
8. 记 SHA256：`Get-FileHash <apk> -Algorithm SHA256`，写进 `docs/acceptance/seg0/D1/README.md`。

## 六、失败时的退出顺序（不许乱试）

1. 构建失败先看 EAS 日志里的**第一条红字**，不要从最后一行往上猜。
2. `eas` 连不上/超时 → 确认代理环境变量已设。
3. 手机装不上：
   - `INSTALL_FAILED_UPDATE_INCOMPATIBLE` = 签名不同（之前装过别的包）→ `adb uninstall com.faze.app` 后重装，**不要换 keystore**
   - 其他 `INSTALL_FAILED_*` → 先卸载再装
4. 装上白屏 → 九成是 baseURL 内联成了 `localhost`，或 JS bundle 崩了；`adb logcat ReactNativeJS:V` 看第一条红字，用正确 IP 重新构建。
5. 三条通道全不通 → 这不是工程侧能自己决定的，报主理人（总纲 §5.1 风险表最后一条）。
