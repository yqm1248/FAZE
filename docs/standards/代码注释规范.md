# 代码注释规范

本规范的密度要求来自 `zxz-bi-server` 薪资包（xzb）的实现，是**最低要求**，不是建议。
判断标准不是"代码能不能看懂"，而是"**换一个人能不能不问人就看懂业务意图、边界和原因**"。

## 1. 总原则

注释必须写出代码无法安全表达的信息：

- **业务目的**：这段代码在满足什么业务规则
- **处理阶段**：长流程里现在是第几步、为什么是这个顺序
- **原因与约束**：为什么必须这样，不这样会出什么问题
- **边界与例外**：什么输入不成立，什么情况会走另一条分支
- **数据口径**：数值单位、精度、来源、是否快照
- **风险点**：可能踩的坑、后续要改的地方

**禁止**机械复述代码：

```ts
// 设置用户名
setUserName(name);           // ✗ 废话

// 顶栏展示的问候语固定为通用文案，不读取用户信息；后续接入登录态后改为按时间段动态生成。
setGreeting('下午好！');      // ✓ 说明取舍与后续计划
```

## 2. 文件头块注释（强制）

每个 `.ts` / `.tsx` 文件顶部必须有块注释，包含四段：

```ts
/**
 * 首页（tab 1）—— 法律服务的入口聚合页。
 *
 * 路由：`/(tabs)/` 即 `/`，登录后由启动页 reLaunch 进入。
 * 数据：全部来自 `__fixtures__/home.fixture.ts`，暂无后端接口。
 * 结构：顶部渐变 banner → AI 解答卡（搜索 + 三宫格）→ 每日学法列表。
 *
 * 注意：顶部 banner 的渐变终点色必须等于页面底色（`color.background.canvas`），
 * 否则渐变底部会接出一条硬边，这是原项目首页的核心视觉细节。
 */
```

要求：

| 段落 | 内容 |
| --- | --- |
| 标题行 | 页面/模块名称 + 一句话职责 |
| 路由 | 只有页面文件需要写，说明路径与进入方式 |
| 数据 | 数据来源（fixture / hook / 后续接口） |
| 注意 | 该文件最容易改错的一点，没有可省略 |

## 3. 组件与函数注释（强制）

**所有导出物**（组件、Hook、工具函数、常量）必须有注释。组件注释写四件事：
做什么、渲染什么结构、交互会触发什么、有什么前置条件。

```ts
/**
 * 律师列表卡片。
 *
 * 左侧竖版头像（65×80）顶部叠一条品牌色状态带，右侧为姓名行、律所、擅长标签、评分与"立即咨询"按钮。
 * 点击卡片与点击按钮都跳转律师详情，参数为去掉"律师"后缀的姓名。
 *
 * @param lawyer 律师展示数据，见 `lawyer.types.ts` 的 `LawyerListItem`
 * @param onPress 点击卡片时的回调，由列表页负责导航
 */
```

私有辅助函数**不是不需要注释**。只要它承担流程步骤、数据拼装、格式化、状态判断，
就必须用同样的标准写。

## 4. 复杂流程的阶段注释（强制）

一个函数里超过 3 个逻辑步骤时，按阶段写明"做什么 + 为什么"。写法沿用薪资包的"任务 n"风格：

```ts
// 任务 1：读出登录态；启动页必须在跳转前判定，避免已登录用户被弹到登录页。
const token = await readToken();

// 任务 2：已登录进首页，未登录进登录页；用 replace 而非 push，防止返回键退回启动页。
await router.replace(token ? '/' : '/(auth)/login');
```

## 5. 样式与令牌注释（强制）

样式表不是"不需要注释"的区域。以下位置必须写注释：

1. **非常规数值**：为什么这个元素是 65×80 而不是方正比例。
2. **与其他元素对齐的数值**：例如"卡片外边距与页面横向边距一致，保证全站左边线对齐"。
3. **为还原原设计而保留的细节**：例如阴影、圆角方向（气泡尖角）。
4. **平台差异处理**：iOS 安全区、Android elevation。

```ts
const styles = StyleSheet.create({
  thumb: {
    // 原项目律师头像为竖版 130×160rpx（65×80pt），比常见方形头像更窄更高；
    // 改成方形会破坏卡片右侧信息区的行数与按钮位置，故保持竖版比例。
    width: tokens.size.listThumbWidth,
    height: tokens.size.listThumbHeight,
  },
});
```

## 6. 设计令牌引用注释

`shared/theme/tokens.ts` 中每个令牌组必须有注释说明**取值来源**：

```ts
/** 品牌色。取自原首页语言切换按钮文字色 `#4e6ef2`。 */
brand: { ... }
```

新增令牌必须写"这个值取自原项目哪个文件哪一行"，否则审查不通过。

## 7. TODO / FIXME / TEMP（强制格式）

```ts
// TODO(owner: 待定, scope: progress): 进度时间轴目前写死 2 个节点，接入接口后按数组渲染。
// FIXME(severity: low): 律师详情的好评率字段当前显示为 `98%`，原项目列表页用 `4.9`，两者口径未统一。
// TEMP(expire: 接入后端时删除): AI 回答为固定文案，仅在输入包含"借钱不还"时返回。
```

没有 owner 和范围的 TODO 不允许提交。

## 8. 注释覆盖检查表

| 位置 | 是否必须 |
| --- | --- |
| 文件头块注释 | 必须 |
| 导出组件 / Hook / 函数 | 必须（含 `@param` / `@returns`） |
| 导出常量、类型 | 必须（类型字段逐字段注释成员语义易混时） |
| 私有辅助函数 | 承担流程步骤时必须 |
| 复杂样式数值 | 必须 |
| 设计令牌组 | 必须写取值来源 |
| 阶段注释 | 单函数 3 步以上必须 |
| `TODO/FIXME/TEMP` | 必须带 owner/范围/失效条件 |
