# 探针与流式约定（段 0 起生效）

> **为什么有这份文件**：段 3 的 AI 问答要复用段 0 的流式读取；如果各段自己写一套，
> 「首字节口径」「SSE 事件名」「ngram 依据」三处必然漂移。代码在 `shared/api/sse.ts` 与
> `infra/probe/`，本文件是导读与口径定义。

---

## 一、SSE 读取：唯一入口是 `expo/fetch`

| 方案 | 结论 |
|---|---|
| RN 全局 `fetch` | ❌ **不能用**。RN 0.81 的全局 fetch 建在 XHR 上（`whatwg-fetch` → `XMLHttpRequest`），`response.body` 是 `undefined`、没有 `getReader()` |
| `EventSource` | ❌ 不能带自定义头（token 只能进 URL，违反「禁止 token 放 URL」），且只支持 GET |
| **`expo/fetch`** | ✅ **采用**。`expo` 54 自带，`response.body` 是 `ReadableStream`，数据由原生模块逐块推给 JS |
| `react-native-sse` | 备选。**只在 `expo/fetch` 真机不逐块回调时启用**，需登记依赖 |

**硬约束**：`getReader()` **只允许出现在 `shared/api/sse.ts`**（`0-A5` 算做完第 7 条）。

**`TextDecoder` 的不确定性**：Hermes 是否暴露全局 `TextDecoder` 未在本机实测。`sse.ts` 做了
`typeof TextDecoder` 探测，缺失时抛明确错误；**不要在 Hermes 里引 `buffer` 包**（体积与兼容性都不值）。

## 二、SSE 事件协议（段 0 冻结）

```text
event: meta   data: {"mock": true|false}
event: delta  data: {"text": "..."}
event: done   data: {"totalChars": N, "firstByteMs": M, "mock": true|false}
event: error  data: {"code": 508001, "msgKey": "error.ai.service-down"}
```

- **首帧必须是 `meta`**：验收记录依赖它判断「本次是否 mock」，不能靠外部猜。
- `done` 是正常结束；`error` 是失败结束，二者必居其一。

## 三、首字节口径（**有一处对文档的技术性让步**）

D3 原文要求「写进响应头 `X-First-Byte-Ms`，并在流末尾发一条 `event: meta` 带上同一数值」。

**实测结论：响应头做不到。** SSE 的响应头在**首帧 `meta` 发出时就已提交**，
而首字节时间要等第一个 `delta` 到达才知道——顺序上不可能。

**当前实现**：
- 首字节耗时（毫秒）= 第一个非空 `delta` 到达时刻 − 开始拉流时刻
- **由 `done` 帧的 `firstByteMs` 承载**（不设响应头）
- 客户端同时测一次，页面显示两个数：「客户端 XXXms / 服务端 YYYms」

**为什么要两个数**：只看客户端测不出「是服务端慢还是网络慢」。分责方法：
- 服务端自己就 > 5s → 上游慢（换推理接入点 / 降 `max_tokens` / 换 region）
- 服务端 < 5s 而客户端 > 5s → 网络与首包（换网络、关代理、确认没走 172.x 虚拟网卡）

**`0-A5` 的判据是首字节中位数 ≤ 5000ms**，用客户端数判定，服务端数用于分责。

## 四、mock 的边界（不许冒充）

- `faze.probe.ai.mock=true` 或 key/model 为空 → 走本地 mock 流（每 30ms 一块）。
- **mock 状态下 `0-A5` 记「未通过」**，不许拿 mock 当豆包。页面 meta 帧与 done 帧都会标明 `mock` 值。
- key 只从环境变量 `FAZE_DOUBAO_API_KEY` 取，仓库里只有 `.env.example` 与 yml 的 `${...}` 占位。

## 五、ngram 检索口径

- 索引：`law_item` 的 `FULLTEXT KEY ft_law_content (content) WITH PARSER ngram`
- 分词粒度：**`ngram_token_size` = 2**（实测）。**`kw` 少于 2 字必然 0 命中**——这是分词器行为，不是 bug。
- 查询用 `MATCH(content) AGAINST (?)`，**禁止改成 `LIKE`**（那样探针就验不出索引是否可用）。
- `matchedTerms`：按与 MySQL **同口径**的 2 字滑窗切 `kw`，再筛出在原文里实际出现的 token。
  实现见 `LawSearchService.ngramTokens`（含「英文按词整体保留」的近似说明）。
- 数据：`V2__init_law_items.sql` 5 条（进 Flyway）；`database/seed/law_items_probe.sql` 探针种子（不进 Flyway，可重复执行）。

**种子为什么不是 50 条**：D3 同时规定「不许自己编法条原文」。技术侧能确认的权威原文只有《民法典》5 条，
其余必须由法务提供——**编造条文比数量不足更糟**（AI 引用假条文是产品事故）。判据只要求「命中 ≥1 条 +
`matchedTerms` 非空 + 空结果不崩」，5 条够验。

## 六、`@Profile("!prod")` 规则

三个探针接口（`ping` / `probe/ai` / `probe/law`）**只在非生产 profile 注册**：

- 理由：`probe/ai` 会真实消耗豆包配额且无鉴权；
- 验收要有「prod profile 下 404」的证据（已做，见 `docs/acceptance/seg0/_artifacts/A3-prod404-*.txt`）；
- 生产下 404 必须是 JSON（`code=401004`），不是 Tomcat 的 HTML 页。

## 八、浏览器自测的 CORS（仅 dev）

真机 RN 不受同源限制，所以 A3 的「段 0 不加 CORS」对真机成立。但 `expo start --web` 在浏览器里跑时，
页面在 `:8090`、接口在 `:8081`，**跨域**——实测所有请求都变成 `kind=network`。

因此加了 **`config/CorsConfig`（`@Profile("!prod")`）**：

| 项 | 值 |
|---|---|
| 允许源 | `http://localhost:8090`、`http://127.0.0.1:8090`（**不写 `*`**） |
| 允许方法 | GET/POST/PUT/PATCH/DELETE/OPTIONS |
| 暴露响应头 | `X-Trace-Id`、`X-First-Byte-Ms` |
| 生产 | **bean 不存在** → `SecurityConfig` 的 `.cors(withDefaults())` 退化为空配置，不放开任何源 |
| 配置项 | `faze.probe.web.allowed-origins`（逗号分隔，可覆盖） |

**这不是给真机用的**，也不改变 A3 的鉴权决策；它只服务「浏览器里自测」这一个场景。
