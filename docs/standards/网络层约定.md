# 网络层约定（段 0 起生效，段 1~8 一律照此）

> **为什么有这份文件**：`shared/api/client.ts` 是全仓**唯一**网络出口。它封装的每一条规则
> 都对应一次具体的线上故障形态（无限刷新、刚登录就被踢、断网白屏、真机连不上）。
> 段 1 起每加一个接口都会经过它，写错一次就是全站问题，所以规则写在代码之外单独一份。
>
> 代码位置：`apps/mobile-app/shared/api/`。**实现是权威，本文件是导读**；两者不一致时以代码为准，
> 并把差异改回来。

## 一、baseURL：一处读取、缺配置即失败

```ts
// shared/api/client.ts 顶部，全仓唯一读取点
const configuredBaseUrl = Constants.expoConfig?.extra?.apiBaseUrl as string | undefined;
if (!configuredBaseUrl) throw new Error('[api] extra.apiBaseUrl 未配置：…');
```

| 规则 | 理由 |
|---|---|
| 值来自 `app.config.ts` 的 `extra.apiBaseUrl`（它读 `EXPO_PUBLIC_API_BASE_URL`） | `extra` 会进 manifest，探针页能把「当前连的是哪台机器」显示给验收人；`EXPO_PUBLIC_*` 直读是构建期内联，改地址要重新构建 |
| **缺配置直接抛错，不静默回退 `localhost`** | 静默回退在真机上表现为「一直网络错误」，最难查 |
| 真机必须用 PC 的**局域网 IPv4** | `localhost` 指向手机自己；`10.0.2.2` 只对 Android 模拟器有效 |
| Windows 防火墙放行 8081 | 否则手机浏览器也打不开 `http://<PC-IP>:8081/api/v1/pub/ping` |

## 二、请求头：8 个，一个不多一个不少

《接口规范》§4.1 的表是 **8 行**；第 9 个 `X-Trace-Id` 是**响应头**，不是请求头。
(`docs/BASELINE.md` 索引里写的「9 个请求头」是口径错误，以此表为准。)

| Header | 值来源 | 何时带 |
|---|---|---|
| `Authorization` | `Bearer ` + access token | 除 `pub` 接口外（登录必须 `auth: false`） |
| `Content-Type` | `application/json;charset=UTF-8` | 有请求体时 |
| `X-Request-Id` | `crypto.randomUUID()`；**同一次逻辑请求重试复用同一个** | 总是 |
| `Idempotency-Key` | `<业务类型>:<业务单号>` | **段 0 不传**；段 1 起只用于「产生资金流水或不可逆状态迁移」的接口（接口规范 §6.4） |
| `Accept-Language` | 当前语言码 | 总是 |
| `X-Client-Version` | `Constants.expoConfig?.version` | 总是（不引 `expo-application`） |
| `X-Client-Platform` | `Platform.OS` | 总是 |
| `X-Device-Id` | SecureStore `faze.deviceId`（首次启动生成 UUIDv4） | 总是 |
| （响应）`X-Trace-Id` | 与 body `traceId` 同值 | 上报错误时带上 |

> **`deviceId` 的双处一致性**：登录请求体里的 `deviceId` 与请求头 `X-Device-Id` 必须是同一个值。
> 两边都走 `tokenStore.getDeviceId()`，不许各自生成。

## 三、错误归一：三种 kind，永不抛异常

`client.ts` 把一切失败收敛成 `ApiResult<T>`：

```ts
type ApiResult<T> = { ok: true; data: T } | { ok: false; error: AppError };
type AppError =
  | { kind: 'business'; code: number; msgKey: MessageKey; traceId: string | null }
  | { kind: 'network';  msgKey: MessageKey; traceId: null }
  | { kind: 'parse';    msgKey: MessageKey; traceId: string | null };
```

| 规则 | 理由 |
|---|---|
| **不抛异常**，失败走 `{ ok: false }` | 渲染层进错误态而不是崩溃（`0-A8` 的基础） |
| `code === 200` 时 `data` 为 `null` **不算错误** | 接口规范 §5.1 约束 1：`data: null` 是保留字段 |
| **`R.msg` 绝不直接展示** | §5.1 约束 2：只给开发者看；展示一律 `t(msgKey)` |
| 未登记的业务码 → 兜底 `error.common.server` | 段 0 只登记 6 个码，整表填充是段 8 的事 |
| 每个请求都有 `AbortController` + 15 秒超时 | 没有超时，断网表现是「一直转圈」而不是错误态 |

## 四、401：三条判据，缺一条就出故障

判据：**`resp.status === 401` 且 `body.code ∈ {402002, 402003}`**。

| 分支 | 动作 | 不这么做会怎样 |
|---|---|---|
| `402002`（过期，可刷）且本次请求**带了 Authorization** | 单飞刷新 → 成功则**重放 1 次**（复用同一 `requestId`） | 不重放 = 用户每次 token 过期都要手动重开 App |
| `402003`（无效，不可刷） | `expireStoredSession(被拒 token)` → `emitUnauthorized()` | 继续刷新 = 无限刷新循环 |
| 刷新接口**自身**返回 401 | 直接登出，**不再触发刷新** | 递归刷新 |
| 请求**没带** Authorization（如登录密码错） | 只当业务错误，**不判登出** | 用户在登录页输错密码会被「踢回登录页」 |
| 迟到 401（被判的 token ≠ 当前存的 token） | 丢弃这次登出 | 把刚登录的新会话清掉，表现为「刚登录就被踢」 |

**单飞**：模块级 `let refreshing: Promise<boolean> | null`，并发请求共享同一个 Promise。
理由：refresh token 是**轮换**的，若 3 个并发请求各自刷新，后两个必然失败。

## 五、存储键（`shared/api/tokenStore.ts` 集中定义）

| key | 内容 |
|---|---|
| `faze.accessToken` | access token |
| `faze.refreshToken` | refresh token |
| `faze.deviceId` | 首次启动生成的 UUIDv4 |
| `faze.lang` | 语言偏好 |
| `faze.rtlPrevPath` | 切换方向前的路由（软重启后回原页） |

**用户资料不落盘**：SecureStore 的单值上限对长 JSON 不友好，且资料应每次启动拉取。

## 六、禁止事项（段 1~8 施工方必须遵守）

1. **页面不许 `fetch`**。全仓只有 `shared/api/client.ts` 与 `shared/api/sse.ts`（D3 建）允许出现 `fetch`。
2. **页面不许 import `expo-secure-store`**，一律经 `tokenStore` / `client`。
3. **`client.ts` 不许 import `expo-router`**（循环依赖 + 单测无导航容器）。登出通知走 `authEvents`。
4. **不许把 `R.msg` 放进 UI**，一律 `t(msgKey)`。
5. **不许在 `client.ts` 之外实现 401 判断**——两处判据必然漂移。
6. PC 后台是 `HTTP 200 + code=401`（RuoYi 前端的拦截规则），**与 C 端判据不同**，段 1 接入时另写，别照抄本节。

## 七、验证方式（都可命令行复跑）

```powershell
# 唯一出口成立
git grep -n "fetch(" -- apps/mobile-app ':!*shared/api/client.ts' ':!*shared/api/sse.ts'

# 导航解耦成立
git grep -n "expo-router" -- apps/mobile-app/shared/api

# 页面不直接读存储
git grep -n "expo-secure-store" -- apps/mobile-app/features
```

三条命令都应输出「无匹配」。
