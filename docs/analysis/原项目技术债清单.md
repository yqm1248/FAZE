## 债务清单

### 1. 配色不是一套设计，是 6 套拼在一起

去重统计到 **57 个色值写法**（含 `uni.scss` 模板自带变量）。业务主色有 5 个互不相干的源头：

| 出处 | 主色 |
| --- | --- |
| 登录 / 注册 / 我的 / 起诉状 | `#154A94 → #1A73E8` 深蓝 |
| 律师列表 / 进度 / 筛选 | `#2C9696` 青绿 |
| 律师详情 | `#6A82FB → #FC5C7D` 紫粉渐变 |
| 案件中心 | `#A52A2A → #7B1D1D` 红棕 |
| 律师入驻 | `#7289DA` Discord 蓝紫 |
| 首页 | `#D2E3FB` 渐变 + `#4E6EF2` + `#8A2BE2` |

**处置**：只保留首页体系，其余按映射表替换。见 [../design/设计令牌.md](../design/设计令牌.md)。

### 2. 藏文字体是死代码，且字体本身不可用

- `pages/index/index.vue:141` 与 `pages/progress/progress.vue:89` 声明 `font-family: 'TibetanFont'`。
- 全项目**没有一处 `@font-face`**，`static/fonts/tibetan.ttf`（51,424 B）从未被加载。
- 实测该字体：族名 `Tibetan Modern A`，**glyph 总数 234，无 GSUB/GPOS 表**。
  藏文上下叠写依赖 GSUB 字形替换，该字体无法正确排版现代 Unicode 藏文。

**处置**：整体废弃。本次只做简体中文，不引入藏文（用户决策）。

### 3. 案件页整页用 HTML 语义标签写

`pages/case/case.vue:4-70` 使用 `<header>` `<h2>` `<main>` `<section>` `<div>` `<span>`；
`:81` 用 `alert()`；`:87` 在 `<style scoped>` 里写 `:global(html, body)`；使用 `100dvh`。

这些只在 H5 端成立，在 App 端语义与样式均失效。

**处置**：全部改为 `View` / `Text`，`alert` 改 `AppToast`。

### 4. tab 图标是 24px 位图，且选中态无区分

`dibu1.png`…`dibu4.png`、`znt.png` 实测均为 **24×24**；高分屏显示发虚。
`pages.json:100-127` 中 `selectedIconPath` 与 `iconPath` 指向同一个文件，选中态仅靠文字变色。

**处置**：按用户要求沿用原 PNG 作 tab 图标；其余图标改用矢量。

### 5. 应用 logo 是 uni-app 默认模板图标

`static/logo.png` 实测 72×72，内容为绿色「U」字（uni-app 模板占位图）。
且被 `pages/lawyer/join.vue:17` 当作「学生身份」的图标使用。

**处置**：按用户要求沿用素材，但已在 [../design/组件清单.md](../design/组件清单.md) 记录此事实。

### 6. 同一份律师数据写了两份，字段口径不一致

- `pages/lawyer/lawyer.vue:74-115`：列表用 `score: '5.0'`、`consults: '2k+'`
- `pages/lawyer/detail.vue:62-103`：详情用 `score: '98%'`，但标签是「好评率」

同一个 `score` 字段在列表页是 5 分制评分、在详情页是百分制好评率。跨页传参靠
`name` 字符串去掉「律师」后缀再查表（`lawyer.vue:129`）。

**处置**：合并为单一 `lawyers.fixture.ts`，字段明确为 `rating`（5 分制）与 `approvalRate`（百分制）两个字段。

### 7. 全程没有网络层

- `pages/auth/login.vue:95`：登录成功 = `uni.setStorageSync('user_token', 'true')`
- `pages/ai-agent/ai-agent.vue:57`：只有输入包含「借钱不还」才返回固定文案
- `pages/tools/lawsuit-form.vue:96-97`：生成起诉状只写 `localStorage`，预览页被注释掉

**处置**：本次为纯 UI，数据统一进 `__fixtures__`；接入后端时替换数据层，不动页面结构。

### 8. i18n 双轨并行

`main.js:16-29` 安装了 `vue-i18n`，但只有首页实际使用；
`pages/progress/progress.vue:62-83` 又在组件内部自建 `dataMap` 绕开 i18n。

**处置**：本次不做多语言，删除 i18n 依赖；如后续需要，统一走 i18n 方案，禁止页面内建翻译表。

### 9. 启动白屏两次

`pages.json:3-9` 第一项是 `pages/auth/splash`，而 `splash.vue:24` 又等 2.5 秒后
`reLaunch` 到 login 或 index。用户会先看到原生启动屏，再看到自制启动页。

**处置**：保留 2.5 秒品牌页（有观感价值），但改用 `router.replace`，并在 `app.json` 关闭重复的原生启动屏停留。

### 10. 零组件化、零类型

12 个页面全部把模板、逻辑、样式写在单个 `.vue` 文件里，最大 271 行；
无任何共享组件，无 TypeScript，无 lint 配置。

**处置**：按 `feature-first` 拆分，共享组件下沉 `shared/`，TypeScript strict + ESLint。

## 有意保留的部分

以下是有产品价值的，不属于技术债：

1. **信息架构**：5 tab（首页 / 律师 / 智能体 / 案件 / 我的）的划分合理，职业服务类 APP 的标准结构。
2. **首页信息密度**：渐变 banner + AI 三宫格 + 每日学法的三段式，一屏内既有品牌感又有功能入口。
3. **律师卡片版式**：竖版头像 + 状态带 + 三行信息 + 底部按钮，比其他法律服务 APP 的方正列表更有辨识度。
4. **进度时间轴**：案件编号 + 状态标签 + 节点时间轴，符合法律服务的用户预期。
5. **表单分组**：起诉状页按「原告 / 被告 / 诉讼请求 / 事实与理由」分组，与真实起诉状结构一致。
