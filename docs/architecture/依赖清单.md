# 法泽 FAZE · 依赖清单（V1.0）

> **为什么有这个文件**：`AGENTS.md` §4.12 要求「新增依赖必须先说明理由，并登记到 `docs/architecture/依赖清单.md`」。这份清单只登记**为满足某条验收锚点而新增**的依赖，不重复登记框架自带的东西。
> **判定标准**：装它能解决一个具体问题；不装它就得自己写 200 行以上，且有明显风险。
> **生成日期**：2026-11-02（第 7 段工作流产出）

## 一、本段新增 4 项（第 7 段）

| # | 依赖 | 版本 | 用途 | 为什么必须加 | 不加的代价 | 风险 |
|---|---|---|---|---|---|---|
| 1 | `spring-boot-starter-actuator` | 随 Spring Boot 4.0.3 | 暴露 `/actuator/health`、`/actuator/prometheus` | `7-A7` 要求「抓到接口 QPS、延迟、错误率」——没有 actuator 就没有指标端点 | 自己写一个指标 HTTP 接口，且 health 探活也没有 | 端点暴露面变大：**必须限制 `management.server.address=127.0.0.1` 且 `/actuator/**` 除 health 外都要鉴权** |
| 2 | `micrometer-registry-prometheus` | 随 SB4 的 BOM | 把 Micrometer 指标导出成 Prometheus 文本格式 | 同上；`actuator` 只是容器，没有 registry 就没有 `/prometheus` 端点 | 同上 | 无（纯导出格式） |
| 3 | `logstash-logback-encoder` | 7.4 | 把日志输出成 JSON（含 `traceId` 字段） | 技术路线 §17.3 明文要求「应用日志统一 JSON 格式」；`7-A6` 要按 traceId 串链路 | 用 pattern 手拼 JSON 字符串，转义容易出错 | 与 SB4 的 logback 版本可能冲突；**冲突时退化为 pattern 输出 JSON 字符串**（第 7 段工作流 G4 已给兜底方案） |
| 4 | `echarts`（前端） | 5.x | A-02 的订单量趋势折线图 | A-02 设计稿画了折线图，注释明确要求「4 条网格线 / 面积 14% 透明 / 峰值点唯一 / 横轴隔天」 | 手写 SVG 折线图，这四条细节全要自己算 | 体积大：**按需引入** `echarts/core` + 折线图 + 柱状图两个模块，不引全量 |

## 二、登记规则

1. **先说明理由再装**。理由要写「解决哪条验收锚点 / 哪个规范条款」，不写「可能有用」。
2. **写清不加的代价**。如果「不加也能凑合」，那就不该加。
3. **写清风险与兜底**。特别是与框架版本冲突时的退路。
4. **禁止**为「让编译通过」而降低 `tsconfig` 的 `strict`、或引入 `@ts-ignore` 类依赖。

## 三、待评估（不装，记录在案）

| 依赖 | 为什么暂不装 |
|---|---|
| `Alertmanager` | 告警通道也是 webhook，但配置与调试成本高；第 7 段用「Prometheus 规则 + 60s 轮询 + 钉钉」实现（G2 已说明是取舍） |
| `node_exporter` | 只提供 CPU/内存/磁盘指标；`7-A8` 用接口错误率就能验，装不装不影响验收（第 7 段标为可选） |
| `logstash` / `ELK` | 需 3 个服务，本机跑不动；JSON 文件 + `Select-String` 已能满足验收 |
| `zipkin` / `otel-collector` | 分布式追踪在单机开发期无价值；`traceId` 已能串链路 |
