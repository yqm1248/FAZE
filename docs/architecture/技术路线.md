### 2.2 路由约定

| 约定 | 规则 |
| --- | --- |
| 路由常量 | 全部集中在 `shared/navigation/routes.ts`，页面不写路径字符串 |
| 参数传值 | 用 `useLocalSearchParams`，参数名与原项目一致（如 `name`） |
| 详情页 | 动态段 `[id]` / `[name]` |
| 启动页 | `/`（`app/index.tsx`），2.5 秒后按登录态 `replace` |
| tab 首页 | `/home`（不能用 `/`，与启动页冲突） |
| 404 | `app/+not-found.tsx` |

### 2.3 状态与数据流

```text
页面 ──► Hook（features/<domain>/hooks/useXxx.ts）──► shared/api/client.ts ──► 后端
              │
              └──► loading / error / empty 三态进 shared/components
```

规则：

1. 页面不直接 `fetch`，只调 Hook。
2. 全局状态只有两项：登录态（`shared/auth/AuthContext`）、语言态（`shared/i18n`）。
3. 其余状态用 `useState` + Hook 封装，不引入状态库。
4. 接口返回统一形状 `{ code, msg, data }`，异常在 `shared/api/error.ts` 归一化。

### 3.2 业务域划分（八域）

| 域 | 职责 | 关键约束 |
| --- | --- | --- |
| `account` | 登录、注册、验证码、实名/企业认证、注销、令牌 | 认证状态只在本域流转 |
| `lawyer` | 入驻四步、审核状态机、列表筛选、收藏关注 | 审核状态只在本域流转 |
| `conversation` | 会话、消息、已读、撤回、附件 | `(user_id, lawyer_id)` 唯一 |
| `trade` | 订单状态机、支付回调、退款、评价 | 金额以回调为准，幂等 |
| `document` | 模板、动态字段、生成、草稿/成品、签章 | 生成走服务端 |
| `caseflow` | 立案、进度时间轴、送达 | 时间轴只追加 |

| `ai` | 问答、检索、会话记录 | 回答全量落库 |
| `ops` | 消息中心、投诉、FAQ、通知 | — |

### 3.3 接口规范

| 项 | 规范 |
| --- | --- |
| 风格 | REST，`/api/v1/<domain>/<resource>` |
| 统一响应 | `{ code: number, msg: string, data: T }`；`code=200` 成功 |
| 分页 | 请求 `pageSize` + `cursor`；响应 `{ list, nextCursor, hasMore }` |
| 时间 | 请求/响应统一 ISO 8601 字符串，库内存 `DATETIME` |
| 金额 | **整数分**（`BIGINT`），接口传分，前端负责展示转换 |
| 鉴权 | `Authorization: Bearer <JWT>`，无状态；Redis 存黑名单 |
| 错误码 | 五位数字：`1xxxx` 通用、`2xxxx` 账户、`3xxxx` 律师、`4xxxx` 会话、`5xxxx` 交易、`6xxxx` 文书、`7xxxx` 案件、`8xxxx` AI |
| 幂等 | 写操作带 `Idempotency-Key` 头，Redis 存 24 小时 |

### 3.4 数据库规范

- 所有表：`id BIGINT AUTO_INCREMENT`、`created_at`、`updated_at`、`deleted_at`（逻辑删除）。
- 字符集 `utf8mb4` / `utf8mb4_0900_ai_ci`。
- 外键不用数据库约束，由应用层保证（便于分表与迁移）。
- 索引命名 `idx_<表>_<字段>`，唯一索引 `uk_<表>_<字段>`。

### 3.5 部署

```yaml

  redis:    redis:7-alpine   # 会话、验证码、幂等键

  nginx:    nginx:alpine     # 反向代理、TLS 终止、静态资源
```

| 项 | 配置 |
| --- | --- |
| 服务器 | 4C8G，单机 |
| 操作系统 | Ubuntu 22.04 |
| 对象存储 | 阿里云 OSS 或腾讯云 COS（图片、文书 PDF） |

## 四、IM 实现路线

### 4.1 链路

```text
用户 App ──WebSocket(wss)──► Spring Boot WebSocketHandler
                                │
                                ├─ 握手阶段：JWT 校验 → 绑定 userId
                                ├─ 在线表：Redis Hash  conversation:online
                                └─ 消息落库：conversation_message
```

### 4.2 表结构

```sql
CREATE TABLE conversation (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id       BIGINT      NOT NULL,
  lawyer_id     BIGINT      NOT NULL,
  last_message  VARCHAR(200),
  last_msg_at   DATETIME,
  unread_user   INT DEFAULT 0,
  unread_lawyer INT DEFAULT 0,
  created_at    DATETIME NOT NULL,
  updated_at    DATETIME NOT NULL,
  UNIQUE KEY uk_conversation_user_lawyer (user_id, lawyer_id)
);

CREATE TABLE conversation_message (
  id              BIGINT PRIMARY KEY AUTO_INCREMENT,
  conversation_id BIGINT      NOT NULL,
  seq             BIGINT      NOT NULL,      -- 会话内自增序号，分页游标
  sender_role     VARCHAR(10) NOT NULL,      -- user / lawyer / system
  sender_id       BIGINT      NOT NULL,
  msg_type        VARCHAR(15) NOT NULL,      -- text / image / file / system
  content         TEXT,
  file_url        VARCHAR(500),
  file_name       VARCHAR(200),
  file_size       BIGINT,
  read_at         DATETIME,
  recalled_at     DATETIME,
  created_at      DATETIME NOT NULL,
  KEY idx_msg_conversation_seq (conversation_id, seq)
);
```

### 4.3 数据隔离（三条硬规则）

1. **拉历史只传 `conversationId`**，服务端用 JWT 里的 `userId` 反查是否为会话成员，不是则 403。
2. 分页用 `seq` 游标（`WHERE conversation_id=? AND seq < ? ORDER BY seq DESC LIMIT 20`），**不用 OFFSET**。
3. 发送消息时，`senderId` 一律取自 JWT，**不信任客户端传入**。

### 4.4 已读与撤回

| 功能 | 实现 |
| --- | --- |
| 已读 | 客户端上报 `lastReadSeq` → 服务端更新 `conversation_message.read_at`、重置 `unread_*` → 推送对端 |
| 撤回 | 仅允许发送后 2 分钟内撤回；置 `recalled_at`，内容保留至审计，前端渲染为"消息已撤回" |
| 重连 | 客户端重连后携带 `lastReceivedSeq`，服务端补推该序号之后的消息 |

### 4.5 离线推送

| 平台 | 通道 |
| --- | --- |
| Android | 厂商通道（华为 / 小米 / OPPO / vivo）+ 个推聚合 |
| iOS | APNs（经个推） |

推送只带"有新消息"的通知，不携带消息正文（隐私）。

## 五、支付实现路线

> 项目为演示性质，**不接真实支付渠道**。但资金相关的数据结构、状态机、幂等逻辑全部真实实现，后续接入真实渠道只需替换 `PaymentGateway` 实现类。

### 5.1 网关抽象

```java
public interface PaymentGateway {
    PrepayResult prepay(Order order, PayChannel channel);
    CallbackResult parseCallback(String rawBody, Map<String, String> headers);
    RefundResult refund(RefundRequest request);
}
```

| 实现类 | 说明 |
| --- | --- |
| `MockPaymentGateway` | **当前使用**：1 秒后回调成功，写 `payment_record` |
| `WechatPaymentGateway` | 预留，接真实渠道时实现 |

### 5.2 状态机

```text
                    ┌─────────────┐
                    │  PENDING    │ 待支付
                    └──────┬──────┘
                 支付成功  │  超时/取消
              ┌─────────┴─────────┐
              ▼                   ▼
        ┌───────────┐       ┌───────────┐
        │  PAID     │       │ CANCELLED │
        │  待接单    │       └───────────┘
        └─────┬─────┘
      律师接单 │
              ▼
        ┌───────────┐
        │ IN_SERVICE│ 进行中
        └─────┬─────┘
     服务完成 │  用户退款
       ┌──────┴──────┐
       ▼             ▼
 ┌───────────┐  ┌───────────┐
 │ COMPLETED │  │ REFUNDING │
 │  已完成    │  └─────┬─────┘
 └───────────┘        │ 退款成功
                      ▼
                ┌───────────┐
                │ REFUNDED  │
                └───────────┘
```

### 5.3 三条铁律

1. **客户端只发意图**（`POST /orders/{id}/pay`、`POST /orders/{id}/refund`），状态迁移由服务端判定。
2. **状态迁移用状态机统一校验**，非法迁移抛业务异常（`5xxxx`），不靠 if-else 散落。
3. **回调幂等**：`payment_record` 表对 `(order_id, channel, transaction_id)` 建唯一键，重复回调直接返回成功。

### 5.4 表结构

```sql
CREATE TABLE orders (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  order_no      VARCHAR(32) NOT NULL UNIQUE,
  user_id       BIGINT      NOT NULL,
  lawyer_id     BIGINT,
  service_type  VARCHAR(20) NOT NULL,   -- consult_text / consult_phone / document / case
  amount_cents  BIGINT      NOT NULL,   -- 金额，单位：分
  status        VARCHAR(20) NOT NULL,
  paid_at       DATETIME,
  finished_at   DATETIME,
  created_at    DATETIME NOT NULL,
  updated_at    DATETIME NOT NULL
);

CREATE TABLE payment_record (
  id             BIGINT PRIMARY KEY AUTO_INCREMENT,
  order_id       BIGINT      NOT NULL,
  channel        VARCHAR(20) NOT NULL,  -- mock / wechat / alipay
  transaction_id VARCHAR(64) NOT NULL,
  amount_cents   BIGINT      NOT NULL,
  raw_payload    TEXT,
  created_at     DATETIME NOT NULL,
  UNIQUE KEY uk_payment_order_channel_txn (order_id, channel, transaction_id)
);
```

## 六、文书与签章实现路线

### 6.1 生成链路

```text
模板(template) ──► 动态字段定义(field_schema)
                    │
用户填表 ──► 表单数据(form_data JSON)
                    │
                    ▼
        服务端渲染 ──► Word(poi-tl) / PDF(openhtmltopdf)
                    │
                    ▼
              OSS 存储 ──► 返回预览 URL
                    │
用户签章 ──► 合成签章图 ──► 重新生成带章 PDF
```

### 6.2 模板机制

| 项 | 方案 |
| --- | --- |
| 模板存储 | `doc_template` 表，存 OSS 上的 .docx 模板地址 |
| 占位符 | Word 模板用 `{{field}}` 占位，`poi-tl` 替换 |
| 动态字段 | `field_schema` JSON 定义字段名、类型、校验、是否必填 |
| 多原告/被告 | `field_schema` 支持 `array` 类型，前端渲染为可增删的行 |
| 多语言 | 每种语言一份模板文件，按当前语言选择 |

### 6.3 PDF 中的少数民族文字

| 项 | 要求 |
| --- | --- |
| 字体 | 在 openhtmltopdf 配置中**显式注册** Noto Sans Tibetan / Noto Sans Arabic |
| RTL 段落 | 维吾尔文、哈萨克文段落需 `<span dir="rtl">` 包裹并设置 `direction: rtl` |
| 混排 | 中文与阿拉伯文混排时，数字与案号用 `<span dir="ltr">` 隔离 |
| 验证 | 每种语言文字生成一份样例 PDF，人工目视检查（这是必做的验收项） |

### 6.4 电子签章（演示实现）

| 项 | 方案 |
| --- | --- |
| 手写板 | `react-native-skia` 绘制，导出 PNG |
| 拖拽定位 | `react-native-gesture-handler` + `reanimated` |
| 合成 | 服务端用 `openhtmltopdf` 叠加签章图到指定坐标 |
| 签名记录 | `signature` 表存签名图 URL、签署时间、文书哈希，供追溯 |
| 法律效力 | **不主张法律效力**，关于我们页明示 |

## 七、多语言与 RTL 路线

### 7.1 语言与代码

| 语言 | BCP 47 代码 | 书写方向 | 字体 |
| --- | --- | --- | --- |
| 简体中文 | `zh-Hans` | LTR | 系统字体 |
| 藏文 | `bo` | LTR | Noto Sans Tibetan / Noto Serif Tibetan |
| 维吾尔文 | `ug-Arab-CN` | RTL | Noto Sans Arabic / Noto Naskh Arabic |
| 哈萨克文（中国） | `kk-Arab-CN` | RTL | Noto Sans Arabic / Noto Naskh Arabic |

### 7.2 资源组织

```text
locales/
├─ zh-Hans/  common.json court.json article.json ai.json profile.json
├─ bo/
├─ ug-Arab-CN/
└─ kk-Arab-CN/
```

规则：

1. key 使用扁平点号：`auth.login.phonePlaceholder`。
2. 所有面向用户的字符串必须走 `t()`，**包括** placeholder、`accessibilityLabel`、错误提示、tabBar label、导航标题。
3. tabBar / 导航栏配置必须用函数形式（`screenOptions()` 返回函数），否则语言切换后不更新。

### 7.3 字体加载

| 步骤 | 实现 |
| --- | --- |
| 1 | 字体文件放 `assets/fonts/`，随包分发 |
| 2 | `expo-font` 的 `useFonts` 在根布局加载，`fontsLoaded` 门控首屏 |
| 3 | 藏文字体置于 `fontFamily` **主位**，不能挂 fallback 链尾 |
| 4 | 藏文字体**不做子集化**（GSUB 引用复合字形） |
| 5 | 阿拉伯系字体 `letterSpacing` 必须为 0（否则断连） |
| 6 | 藏文 `lineHeight ≥ 1.6 × fontSize` |

### 7.4 RTL 切换流程

```text
用户选择语言
   │
   ├─ 目标语言 direction 与当前相同（中↔藏）
   │     └─► changeLanguage() → 全树重渲染，不重启
   │
   └─ 目标语言 direction 不同（LTR↔RTL）
         └─► changeLanguage()
             → 持久化 lang
             → Updates.reloadAsync()（软重载，约 1–2 秒启动屏）
             → 重启后读取 lang，I18nManager 生效
```

依据：React Native 官方 `I18nManager` 文档明确「Changes take effect on the next application start, not immediately」。

### 7.5 混排处理

| 场景 | 处理 |
| --- | --- |
| 法条编号 `第12条` | 用 `<LtrText>` 组件包裹，内部加 `U+2066 … U+2069` 隔离符 |
| 案号 `(2023)伊民初字第005号` | 同上，且作为不透明字符串，不做数字格式化 |
| 金额 `-¥500` | 同上 |
| 数字 | 一律使用 0-9，不本地化为 `٠١٢٣`（否则与中文版编号对不上） |

`shared/components/LtrText.tsx` 是这条规则的唯一实现点，页面不得手写控制符。

### 7.6 内容层翻译

| 内容类型 | 方式 |
| --- | --- |
| UI 文案 | 人工翻译 + 母语者校对 |
| 每日学法文章 | 机翻初稿 + 人工校对 |
| 案例详情、法条引用 | 人工翻译，法条原文不机翻 |
| AI 回答 | 不预翻译，后端按当前语言注入语言指令生成 |

内容表结构：

```sql
CREATE TABLE article (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  source_updated_at DATETIME NOT NULL,   -- 原文最后更新时间
  ...
);

CREATE TABLE article_translation (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  article_id BIGINT NOT NULL,
  lang VARCHAR(20) NOT NULL,
  title VARCHAR(200),
  content MEDIUMTEXT,
  status VARCHAR(20),                    -- missing / draft / reviewed
  translated_from DATETIME,              -- 翻译时对应的 source_updated_at
  UNIQUE KEY uk_article_lang (article_id, lang)
);
```

`translated_from < source_updated_at` 即视为「译文已过期」，后台标红提醒。

## 八、AI 接入路线

### 8.1 链路

```text
用户提问
   │
   ├─► 意图与关键词抽取
   ├─► 法条 / 案例检索（关键词 + 向量混合，检索 top 5）
   ├─► 拼装 Prompt（系统指令 + 检索结果 + 术语表 + 语言指令）
   ├─► 调用大模型（SSE 流式）
   ├─► 边接收边转发给前端
   └─► 全量回答落 ai_message 表
```

### 8.2 Prompt 约束

| 约束 | 内容 |
| --- | --- |
| 法条引用 | 只允许引用检索结果中出现的法条，**禁止自行生成条文号** |
| 术语表 | 注入法律术语标准译法，保证多语言一致 |
| 语言 | 按当前 App 语言输出 |
| 免责 | 每次回答末尾附「本回答不构成法律意见」 |
| 格式 | 要求输出结构化：结论 → 依据 → 操作步骤 → 风险提示 |

### 8.3 表结构

```sql
CREATE TABLE ai_message (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  session_id BIGINT NOT NULL,
  user_id BIGINT NOT NULL,
  role VARCHAR(10) NOT NULL,        -- user / assistant
  content MEDIUMTEXT,
  model VARCHAR(50),
  prompt_tokens INT,
  completion_tokens INT,
  refs JSON,                        -- 引用到的法条/案例 ID
  created_at DATETIME NOT NULL
);
```

### 8.4 流式传输

| 项 | 方案 |
| --- | --- |
| 后端 | 该路由单独用 WebFlux `Flux<String>`，不占 Servlet 线程 |
| 前端 | `react-native-sse` 逐段渲染，打字机效果 |
| 中断 | 用户离开页面时 `abort()`，后端同步取消上游请求 |
| 失败 | 前端显示重试按钮，重试走同一 `session_id` |

## 附录：关键技术依据

| 结论 | 依据 |
| --- | --- |
| RTL 切换需重启 | React Native 官方文档 `I18nManager`：`allowRTL` / `forceRTL` "Changes take effect on the next application start, not immediately" |
| 藏文字体须含 GSUB | OpenType 规范：复杂文字排版依赖 GSUB/GPOS，由系统排版引擎（HarfBuzz / CoreText）执行 |
| `kk` 默认西里尔 | BCP 47：`kk` 无书写系统子标签时默认西里尔，中国境内哈萨克文为阿拉伯字母，须写 `kk-Arab-CN` |
| 阿拉伯文 `letterSpacing` 断连 | React Native `Text` 实现：非零字距会破坏阿拉伯字母连接 |
| 语音代码使用 `ug-Arab-CN` | 同上，`ug` 需显式声明 `Arab` 书写系统 |
