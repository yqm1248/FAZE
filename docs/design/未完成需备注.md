## 六、RuoYi 框架层的边界（设计稿据此画，代码不许越界）

**事实**（读 RuoYi-Vue3 **3.9.2** 源码确认；2026-11-01 复核，下列四个尺寸值与 3.8.7 完全一致）：

| 项 | 值 | 能不能改 |
|---|---|---|
| 侧边栏宽度 | 200px（`variables.module.scss` `$base-sidebar-width`） | **不能改**（框架层） |
| 顶栏高度 | 50px（`Navbar.vue`） | **不能改** |
| 标签页高度 | 34px（`TagsView`） | **不能改** |
| 内容区 padding | 20px（`.app-container`） | **不能改** |
| 主色 | Element Plus 的 `--el-color-primary` | **能改**（CSS 变量覆盖） |
| 菜单配色 | `variables.module.scss` 里的 `$base-menu-*` | **能改**（配置覆盖） |
| 业务页面内部样式 | `src/views/biz/<domain>/` 下的组件 | **能改**（这是我们自己的代码） |
| 布局结构（侧边栏+顶栏+标签页+主内容） | `src/layout/` | **不能改** |

**后果**：设计稿必须贴着上表画。自创布局（比如把侧边栏改到顶部、加二级侧栏）在代码层落不了地。

**确需 patch 框架层时**：必须记录到 `docs/analysis/ruoyi-patches.md`（AGENTS.md §3.3 的要求），该文件目前**不存在**，第一次 patch 时创建。

## 七、设计稿本身的已知省略

1. **四态：只画了「正常」态，空态与加载态没画**。这是设计阶段的取舍，不是遗漏——28 屏已经覆盖了 7 类页面范式，再给每屏补空/加载两态会多出 50 多屏，收益低于成本。components.css 里已有 .empty（空态）与 .skeleton（加载骨架）两套组件，开发时直接接。**如果后续要求设计稿必须带空态，按范式补 7 屏（每类范式补一屏）即可，不用补 28 屏。**
2. **不做权限态**：因为只一个角色，不画「无权限」的按钮隐藏/禁用态。
3. **不做深色模式**。
4. **表格数据是设计用的合理假数据**，不是真实业务数据；金额、单号、人名都要能一眼看出是假的（避免被误当真）。实际上设计稿里用的是真实感数据，**开发时替换成接口数据**。
5. **图表用静态 SVG 画**，不引入图表库。
