# 设计令牌说明

令牌的机器可读来源是 [../../design/tokens/tokens.json](../../design/tokens/tokens.json)，
运行时实现是 `apps/mobile-app/shared/theme/tokens.ts`。本文件解释**取值依据**与**变更记录**。

## 1. 为什么配色只取首页

原项目 12 个页面使用了 6 套互不相干的配色体系（去重统计 57 个色值写法）：

| 出处 | 主色 | 问题 |
| --- | --- | --- |
| 登录 / 注册 / 我的 / 起诉状 | `#154A94` 深蓝 | 与首页体系无关联 |
| 律师列表 / 进度 / 筛选 | `#2C9696` 青绿 | 与深蓝并列出现，冷暖冲突 |
| 律师详情 | `#6A82FB → #FC5C7D` 紫粉渐变 | 偏娱乐化，与法律服务调性冲突 |
| 案件中心 | `#A52A2A → #7B1D1D` 红棕 | 三处主色并存 |
| 律师入驻 | `#7289DA` | 接近 Discord 品牌色 |
| 首页 | `#D2E3FB` 渐变 + `#4E6EF2` 蓝 + `#8A2BE2` 紫 | 唯一成体系的一套，冷色淡雅，与法律服务的克制调性一致 |

按"配色以首页为准"的要求，令牌只保留首页体系，其余按
[页面清单与信息架构.md](页面清单与信息架构.md) 第 4 节的映射表替换。

## 2. 单位换算

原项目使用 `rpx`，本项目使用 RN 逻辑像素（dp/pt）。换算基准：

```text
750rpx = 屏宽 = 375dp（iPhone 逻辑宽度）
1rpx = 0.5dp
```

因此原项目的 `24rpx` = `12dp`，`48rpx` = `24dp`。令牌中的 `spacing`/`radius`/`size`
数值已全部换算完毕，**代码中不再出现 rpx 概念**。

### 3.1 对原项目颜色的四处主动加深

原项目配色在桌面显示器上看是协调的，但**放到手机上做正文色就不达标**。
下面四处不是审美调整，是 WCAG AA（正文 4.5:1）的硬门槛：

| 令牌 | 原值 | 现值 | 原值对比度 | 现值对比度 |
| --- | --- | --- | --- | --- |
| `color.text.muted` | `#999999` | `#63696E` | 白底 2.85:1、`#F5F5F5` 底 2.61:1 | 白底 5.56:1 |
| `color.brand.primary` | `#4E6EF2` | `#4A66EE` | 白字压其上 4.31:1 | 4.68:1 |
| `color.state.success` | `#2C9696` | `#1F7A7A` | 白底 3.52:1 | 4.86:1 |
| `shadow.pill` 的色 | `rgba(78,110,242,.3)` | `rgba(74,102,238,.3)` | — | 跟随 primary |

**为什么必须改而不是「看起来差不多就行」**：本产品的目标用户包含中老年人，
以及非汉语母语的少数民族用户。低对比度文字对这两类人群是可读性问题，不是风格问题。

`--text-muted` 那一处对观感影响最大（meta 信息、日期、阅读数全都是这个色），
如果要和原图完全一致，只能接受这几类信息在户外强光下看不清。

### 3.2 字体：阿拉伯系必须自托管

`typography.fontFamily.arabic` 是**唯一必须打包**的字体，其余走系统栈。

原因不是审美：本产品 4 个语言里，维吾尔文（`ug-Arab-CN`）和哈萨克文（`kk-Arab-CN`）
是阿拉伯字母的**连写文字**。中文字体栈（PingFang / MiSans / 微软雅黑）里**没有任何阿拉伯字形**，
不显式指定就一路 fallback 到系统默认字体，结果是：

1. 各机型观感不一致（同样是维语版，iOS 和千元安卓机长得不一样）
2. 部分低端机缺字，出现连写断裂——字母该连的不连，直接影响阅读理解

**实测数据（2026-10-29，`python scripts/fetch-arabic-font.py` 生成，`verify-arabic-font.py` 核验）**：

| 项 | 值 |
| --- | --- |
| 字体 | Noto Naskh Arabic v44（Google Fonts） |
| 许可 | SIL Open Font License 1.1（`design/ui/fonts/OFL.txt` 随附） |
| 文件 | `design/ui/fonts/noto-naskh-arabic.woff2`，94,032 字节 |
| 类型 | 可变字体，`fvar` 轴 `wght` 400–700，默认 400 |
| 码位 | cmap 1225 个 |
| 覆盖 | 维吾尔文 32 字母 + 哈萨克文专用 6 字符，**38/38 全覆盖** |
| 连写 | GSUB 含 `ccmp` / `init` / `medi` / `fina` / `rlig` / `locl` |

> 因为是可变字体，400 和 700 共用同一份文件，`@font-face` 用 `font-weight: 400 700` 声明区间，
> 不要傻存两份 94KB 的相同文件。

**RTL 排版的三条硬规则**（其余见 `tokens.json` 的 `typography.rtlNotes`）：

1. 连写文字**不能设 `letter-spacing`**。中文标题常用的 `-0.01em` 会把该连的字形拉开，RTL 下必须归零。
2. 正文行高用 `lineHeight.rtlArticle`（2.0），不用中文的 1.75——阿拉伯字母上下伸部多，1.75 会挤。
3. 数字和日期用 `fontFamily.numeric` 并做 bidi 隔离，不要跟随正文字体，否则会被 bidi 算法重排。


## 4. 令牌使用规则

1. 页面与组件**只能**通过 `tokens.*` 取得视觉数值。
2. 需要新的数值时：先判断能否复用既有令牌；确实需要新值时，按"新增令牌流程"操作。
3. 透明度需求不要临时写 `rgba()`。两种做法：
   - 使用 `opacity` 样式属性（适用于整块元素）
   - 在 `tokens.ts` 中定义带 alpha 的专用令牌（适用于单色场景），并在 JSON 中登记

### 新增令牌流程

1. 在 `design/tokens/tokens.json` 增加条目，`note` 必须写明"取自原项目哪个文件"或"为什么需要它"。
2. 在 `design/ui/tokens.css` 同步同名变量（设计稿是 JSON 的 CSS 投影）。
3. 在 `apps/mobile-app/shared/theme/tokens.ts` 同步实现（第 0 段建这个文件时从 JSON 生成）。
4. 在本文件第 5 节追加变更记录。
5. 跑 `python scripts/check-tokens-sync.py` 确认 JSON 与 CSS 一致，否则提交不通过。

### 校验脚本

```bash
python scripts/check-tokens-sync.py       # 有偏差则 exit 1
python scripts/check-tokens-sync.py -v    # 打印全部比对项
```

脚本会抓三类问题：值不一致、JSON 缺路径、CSS 有未登记变量。
第 1 批就栽在第三类上——在 CSS 里改了 4 个颜色、补了 10 个变量却没回写 JSON，
人眼完全看不出来，`tokens.json` 就此变成一份和真实渲染不符的"假来源"。**这个脚本是那笔账的产物。**
