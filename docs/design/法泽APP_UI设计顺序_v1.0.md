# 法泽 FAZE · APP UI 设计顺序（V1.0）

> **这份文档解决什么**：65 个页面**按什么顺序设计**，每批的锚点在哪，复刻与延展怎么分。
>
> **设计原则（项目负责人 2026-10-29 明确）**：
> 1. **风格按原项目那一套复刻**，不重新设计。版式、配色、信息密度、文案都向原项目靠。
> 2. **图标不复刻**：原项目是 24px 位图标，高分屏发虚。改成一整套线性 SVG，但**保留原项目的青 / 蓝 / 橙三色**。
> 3. **图片不复刻**：头像、律师照片、文章封面一律用占位。律师头像将来由律师自己上传。
> 4. **先 APP，平台（PC 管理后台）最后做**。
>
> **定稿**：2026-10-29

## 五、每批的固定流程

每一批都照这个走，不跳步：

1. **写 / 改 `tokens.css`** —— 只在本批需要新变量时才动它
2. **一屏一个 HTML**，同名目录，按批次内顺序写
3. **写完第一屏就 `preview_page`**，后面自动并排
4. **全批写完调 `check_design`** —— 量文字截断、叠字、对比度、点击区、固定栏压内容、脚本报错、死链
5. **调 `look_design`** —— 看层次、留白、配色、整体观感
6. **照问题清单改**，最多三轮
7. **报告**：做了哪几屏、哪些是复刻哪些是延展、还剩什么问题、与原图的差异清单

## 六、复刻到什么程度算够

对**有参考图**的 12 页：

| 项 | 要求 |
|---|---|
| 版式与信息层级 | 一致。同样的区块、同样的顺序、同样的疏密 |
| 配色 | 一致。用 `tokens.json` 里已经定好的值 |
| 间距节奏 | 一致。用令牌里的 spacing 值 |
| 圆角 / 阴影 | 一致。卡片 `12px`、胶囊 `999`、阴影低透明度大模糊 |
| 文案 | 一致。原图的文案直接沿用（「站在你的角度」「每日学法」等） |
| 图标 | **不复刻**。换成线性 SVG，但保留原项目的青 / 蓝 / 橙三色 |
| 图片 | **不复刻**。头像、律师照片用占位 |
| 字体 | 系统字体栈（原项目也是） |

**必须记录差异**：每一屏做完，在报告里列出「与原图的差异 + 为什么改」。不改而看起来不一样的地方，要能解释。

## 七、延展怎么画才不散

对**无参考图**的 53 页，规则是**只允许用已定母版的变体**，不允许发明新结构：

| 要画的东西 | 照哪个母版 |
|---|---|
| 列表页（文章、消息、订单、我的案件、收藏） | 律师列表（吸顶搜索 + 分类 + 卡片列表） |
| 详情页（案例、订单、文书、消息） | 律师详情（渐变头 + 头卡 + 分区 + 底部操作栏） |
| 表单页（立案、认证、反馈、资料编辑） | 起诉状表单（分组表单 + 底部主按钮） |
| 设置类（设置、通知、隐私） | 设置页（分组行 + 右箭头 + 开关） |
| 聊天类（IM、客服） | AI 对话（气泡 + 输入区） |
| 时间轴（进度、送达） | 案件进度（节点 + 激活态） |
| 结果页（立案成功、支付结果） | 新增一个极简母版，做一次即可 |
| 网格页（功能总览、文书模板） | 首页三宫格的放大版 |

**判断标准**：如果一屏里出现了 6 个母版都没有的组件形态，说明要么该补一个母版，要么这一屏画错了。
