## screenshots 的生成方式（踩过的坑，勿重蹈）

截图由 `tmp/cdp-shot.js` 通过 Chrome DevTools Protocol 生成：先用
`Emulation.setDeviceMetricsOverride` 锁定视口为 390×844、DPR 2，再 `Page.captureScreenshot`。

**不要用 `chrome --headless --screenshot --window-size=390,844` 生成对照图**：
实测该方式下 Chrome 的实际视口是 512 宽（受最小窗口宽限制），截图按 390 裁剪，
会把右侧 122px 切掉，从而误判成「布局溢出」。

## 页面实现工作流（真实上线口径）

```text
1. 在《分期交付计划》确认该页属于哪一段 —— 不属于当前段就先别做
2. 在《页面导航树 v1.4》查该页的跳转关系、页面四态、返回逻辑
3. 在《设计令牌》查颜色/字号/间距；在《组件清单》查要用的组件是否存在
4. 写 features/<domain>/pages/<Name>Page.tsx（含文件头注释）
5. 接真实接口：features/<domain>/api/ + hooks/，不写 __fixtures__
6. 写 app/ 下的路由壳（1 行 re-export）
7. 四语言 key 补齐（至少 zh-Hans + ug-Arab-CN），页面四态（正常/加载/空/错误）齐全
8. npm run lint（tsc --noEmit + eslint 零告警）
9. 回《页面清单与信息架构》把状态改成「已完成」
```

> 第 5 步的 **fixture 分支已作废**：原型阶段的工作流是「先写假数据到 `__fixtures__/`」，
> 真实上线不再允许以此为准。页面只认 `hooks` 返回的形状，假数据可在 hook 层用 mock 开关，
> 但**不允许 fixture 进业务代码路径**。

## 视觉还原的判定标准

不是「看起来像」，而是逐项核对：

1. **垂直节奏**：元素间间距的比例关系是否一致（banner 内边距 > 卡片间距 > 列表项内边距）
2. **层级**：卡片阴影、圆角、描边三者是否与原设计同层级使用
3. **信息密度**：一屏内可见的信息条数是否接近（律师卡片的高度决定一屏能放几张）
4. **对齐**：全站左边线是否对齐（卡片外边距与页面横向边距统一为 15dp）
5. **配色**：除状态色外，不出现令牌之外的色相
6. **RTL**（真实上线新增）：维吾尔文/哈萨克文下整屏镜像正确，金额与订单号方向不乱
